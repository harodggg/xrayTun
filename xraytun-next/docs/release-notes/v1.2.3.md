# xraytun-next v1.2.3 —— 产品面只做 TUN：把 SOCKS 代理的痕迹从界面与 CLI 上清掉

> 用户 2026-10-16 裁决：**放弃 SOCKS 代理，只做 TUN。**
> 这一版不是「少做一个功能」，而是把「产品里到底提供什么」这件事在**每一个出口上对齐** ——
> 因为上一个会说假话的 bug（连着 TUN 切节点却掉回 SOCKS）就是「界面说 TUN、底下跑代理」长出来的。

## 改了什么（都是产品面，daemon 的数据面见下）

| 出口 | 以前 | 现在 |
| --- | --- | --- |
| 设置页那张卡 | 标题「**代理入口**」，栏位「SOCKS 监听地址」 | 标题「**本机 API**」，栏位「本机 API 监听地址」，并写明：本版本只做 TUN、daemon 不再提供 SOCKS 入站、这个地址只是 xray 本机 API 的监听基址（统计与控制用） |
| 设置页能力行 | 只把 daemon 声明的能力原样列出来，用户会问「我只做 TUN，为什么有 `proxy_mode`」 | 能力行**仍是线上原文**（不美化），但旁边多一句解释：`proxy_mode` 是给 **CI 端到端验证**留的通路（TUN 需要 root/助手，CI 跑不了），本产品的连接模式只有 TUN |
| `xt-cli connect` | 固定发 `proxy`（界面只做 TUN、CLI 偷偷走 SOCKS） | 固定发 `tun`（`CONNECT_MODE`，有单测钉住）。没装助手时它**像 App 一样如实报错**，不会偷偷换一条能连上的路 |
| 契约文档 | `RunMode::Proxy` / `Capability::ProxyMode` 没写清现状 | 就地写明：**不是产品入口**，只服务 CI 的端到端验证与无头调试 |
| README / DMG 内的说明 | 只说「只有 TUN」 | 补一句：设置页那一栏不是 SOCKS 入口 |

## 保留了什么，以及为什么必须保留

daemon 内部那条 **SOCKS 数据面保留**（`RunMode::Proxy`、`connect_flow` 的代理分支、`Capability::ProxyMode`
仍然宣告）。理由只有一条，但是硬的：

* CI 上**唯一**能证明「真有字节穿过隧道」的端到端用例走的就是它
  （`crates/xt-daemon/tests/e2e_real_xray.rs`：真 xray + 真 SOCKS5 取回真字节、还有反复切节点的轮次）。
* TUN 需要 root 与特权助手（launchd 守护服务），GitHub 的 runner 上装不了 —— 把那条约会一起删掉，
  代价是 CI 从此对数据面**没有任何**证据，只剩「意图被受理 + 失败如实报错」。
* 契约也要求：**未宣告的能力，对应请求必须返回 `Unsupported`**。所以要么留宣告（保住那条 CI 证据），
  要么彻底删（丢掉证据）。用户选了前者，这条口径写进了 `crates/xt-contract/src/model.rs` 与
  `crates/xt-daemon/src/flow.rs` 的注释里，防止下一个人又给它开产品入口。

**它绝不会出现在产品面上**：界面没有模式选择器，设置页不再提「代理」，「连接」一切只发 TUN。

## 证据

- 本机可验：`apps/ui` 全量 `vitest`、`tsc --noEmit` 0 错、`bash scripts/guard.sh` PASSED。
  新增验收 `tests/acceptance/tun-only.test.tsx` 四条：设置页没有「代理入口/SOCKS 监听地址」、
  那一栏说的是它真做的事、能力行保持原文但旁边有解释、那一栏仍然能用（保存真的把值发出去）。
- 只能由 CI 验：`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`
  （含 `CONNECT_MODE == Tun` 单测与 proxy 数据面的真实端到端）。
- 真机（helper 授权、utun、路由与 DNS）**仍然只有你能验**。

## 仍然没有做到的（不许含糊）

- **TUN 真机接管没有验收过**；未公证（Gatekeeper 拦截）以你真机为准。
- daemon 的 SOCKS 数据面还在（见上），所以「本版本没有任何 SOCKS 代码」这句话是**假的** ——
  正确说法是「产品面不提供 SOCKS，它只作为 CI 的验证通路存在」。
- 还有一处本机 SOCKS 端口必须说清：**「测试延迟」**会给每个节点临时起一个本机 xray 实例，
  用**每节点一个环回 SOCKS 端口**去量真实 TTFB（`crates/xt-xrayconf/src/lib.rs` 的 `generate_probe`，
  `listen: 127.0.0.1`）。那是**测量路径**，不是产品连接模式：只绑回环、只在探测期间存在、
  用户既看不到也连不上它。要把它也去掉，就得换一种量真实 TTFB 的办法（TUN 探测需要 root/助手），
  这件事没有做。
- 订阅没有定时自动刷新；托盘「退出」只退界面、隧道继续跑。

## 怎么验（给真人的最短路径）

1. 打开 App（未公证，见 DMG 里的 `首次打开请看这里.txt`）。
2. **设置页**确认那张卡现在叫「本机 API」，且写着「本版本只做 TUN」。
3. **节点**页粘订阅原文/分享链接导入（或**设置 → 订阅**填 URL）→ 点某一行的**「选为当前节点」**。
4. 仪表板按**「启动」**（第一次要装特权助手，一次管理员授权，必须给）。
5. 连上后点另一个节点的**「切换并立即使用」**：应当看到 断开 → 连接，而不是悄悄掉成 SOCKS。
6. 收工：停止；设置页卸载助手（界面写清了删哪三样、留下哪一个目录）。
