## 改了什么，以及为什么

### 1. 「现在通不通」从三处合并为一处

旧版把连接状态拆在三个地方：一张写着 pid 的卡片、顶栏的绿点与「断开」按钮、
以及一条黄色横幅（「路由尚未接管」）。用户得自己把三处拼成结论 ——
而 `docs/05` 第 2 条明确要求「连接成功必须精确表达」。

现在是一个状态区：状态词（带颜色）+ 节点 + 延迟徽章，下面一行把
「模式 · 路由 · 已运行时长」串起来，右侧是唯一的主操作按钮。
**中间态（隧道已建、路由未接管）成为状态词本身**，不再是第四条横幅。

### 2. 横幅从最多 5 条收敛为 1 条

`Notices` 原本有 5 个平铺的 `{cond && <Banner/>}` 分支（路由未接管、
残留会话、找不到核心、核心太老、后端提示），加上底部的 `last_error`，
顺序是**代码顺序而非紧急程度** —— 于是「流量还没走代理」可能排在
「helper 没装」下面。现在统一收集后按严重度排序，只显示最急的一条，
其余折成一行「还有 N 条提示」。

### 3. 流量与诊断降级

* 流量原本是两张占满的卡片、与「当前节点」同权重。现在是一行紧凑文本
  （等宽字体 + 定宽，数字跳动不推挤布局）。
* 进程 pid、配置路径、上次配置变更收进「环境自检与诊断」折叠区 ——
  出问题时才需要看。
* 卡片网格的错位（`minmax(240px)` 在 1080 窗口下排 3 列，第 4 张被迫换行留白）
  随卡片一起消失。

### 4. 直连模式下说明原因

直连模式里连接按钮是禁用的（这是对的：那里该切模式而不是启动一个没用的进程），
但旧版只禁用、不解释。现在禁用时给出一句原因。

## 顺带加的：浏览器预览桥接

`apps/ui/src/preview.ts` + `main.tsx` 里的一段 dev 分支。

**为什么**：界面完全依赖 Tauri 的 `invoke`，在普通浏览器里只会看到
`window.__TAURI_INTERNALS__ is undefined`。于是每改一次样式都要重编整个 Rust
外壳（几分钟），而样式迭代本该是秒级。挂上桥接后布局、样式、交互都能真实渲染。

```bash
cd apps/ui && npm run dev
# 浏览器打开 http://localhost:5173/?preview=1
# 切换场景：&state=connected|uncommitted|disconnected|no-core|stale|notice
```

**生产不受影响**：只在 `import.meta.env.DEV` 为真且 URL 带 `?preview=1` 时
动态加载。`npm run build` 之后已核实产物里不含
`installPreviewBridge` / `scenarioSnapshot` / 任何合成节点数据。
