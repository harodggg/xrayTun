## 默认视角：**既保证装得下，也保证两端分得开**

正交投影下，两点夹角 θ 的屏幕距离是 `2R·sin(θ/2)`（`R = 0.42 × 画布短边 × zoom`）。
这里有两个相反的诉求，`fitZoom()` 同时满足：

* **装得下（上限）**：跨半球时两端要同时进画面 —— `fit = min(1, 0.7 / sin(θ/2))`；
* **分得开（下限）**：近距离航线必须被放大到两端可辨 —— `want = TARGET_SPAN_RAD / θ`
  （`TARGET_SPAN_RAD = 0.7 rad ≈ 40°`）。

```ts
return clampZoom(want > 1 ? want : fit);   // 交接点 θ≈40°，连续
```

**为什么必须要有「分得开」这一半**：广州↔香港只有 **1.163°** 角距，旧规则
（`min(1, 0.7/sin(θ/2))`）让它**恒为 zoom=1**，两点在屏幕上只相距 **4.9 CSS px** ——
两个标记、航线、飞机全糊成一团。这正是用户说的「放大倍数不够」。
现在是 `zoom = 0.7 / 0.0203 ≈ 34.5`，屏幕间距约 **212px**。

两点重合（θ→0）时返回 1：没有航线可言，保持整球可见。

## 缩放范围

| 常量 | 值 | 依据 |
|---|---|---|
| `MIN_ZOOM` | **0.55** | 跨半球时把两端一起收进画面 |
| `MAX_ZOOM` | **40** | 近处航线要能拉开到约 200px；`zoom ≈ 41.9` 对应 200px，取 40（v0.8.23 从 8 提到 40） |

**代价必须写清（真实取舍，不是遗憾）**：大陆轮廓是 **2° 分辨率**的海陆位图
（`landmask.ts`，180×90 格 ≈ 每格 200 公里），放大到 30–40× 时海岸线会**明显发虚**。
它给的是**方位感**，不是地图精度。把位图提到 1°（约 16KB 编码）是后续可选项，本轮没做。

## 验证方式

量缩放时**读画布自身的像素**（`getImageData`），不用截图 ——
球放大后会撞到画布边界被裁剪，看截图的宽度会得到「没变化」的错误结论。

更稳的一条：直接找两个**标记点的实心纯色**（起点 `#34d399` / 终点 `#4f8ef7`）取质心，
质心距离 × CSS 缩放 = 「用户实际看到的两点间距」。CDP 脚本见
`.scratch/globe_measure.py`（仓库外）。

## 近距离航线为什么曾经整屏空白（v0.8.23 修复）

用户反馈「放大倍数不够」后，`fitZoom` 已改为「近处放大、远处缩小」。但放大到
34.5× 之后地球仪**整屏空白** —— 标记与航线全部不可见。两个潜藏 bug 被同时放大：

| # | Bug | 为什么 zoom=1 时看不出来 |
|---|---|---|
| 1 | 纬度居中乘了系数：`lat = focus.lat * DEG * 0.6` | zoom=1 时焦点只偏 48px；34.5× 时偏移被同比放大到 **1287px**（画布上方） |
| 2 | `auto`（自转）恒为 true | 整球可见时自转只是慢慢转；34.5× 时自转 13.5° 让两点横向偏出 **2500px** |

正确的居中关系（数值验证）：经度取负、**纬度直接用 `+φ` 不乘系数** ——
`rotX(+φ)` 把焦点转到正前方 `(0,0,1)`，任意缩放下都精确居中。

修法：
- 抽出 `viewFor()` 统一计算「对准哪里 / 缩放多少 / **是否允许自转**」；
- 自转判据用「两点跨过的角度」：小于 `ROTATE_MAX_SPAN_RAD`（0.06 rad ≈ 3.4°）就关闭自转，
  因为此时视野张开很小、自转会把视野整个扫走。

实测修复后（广州↔香港，zoom=34.47）：
```
view  {lon:-1.9847, lat:0.3966, zoom:34.47}
标记  [(284,286), (436,434)]  z=0.9999   ← 居中对称、相距 ~212px
像素  本机标记 46、节点标记与航线 46、陆地 95
```

回归保护：`apps/ui/src/globe.test.ts` 新增 3 条，且**已回退验证**：
把纬度乘回 0.6 → 「焦点必须投影到画布中心」变红；把 `auto` 改回 true →
「放大后必须关闭自转」变红。
