# xraytun-next v1.2.1 —— 「订阅」这条路是真的了，走查发现的三处死路也补上了

> 上一版（v1.2.0）发出去之后，用户实测结论是**「完全用不了」**：
> 界面上没有地方能把节点弄进来、按「启动」必然撞上没装的 helper。
> 这一版是照「一个刚下载完 App 的普通人会怎么用」重走一遍之后的修补。
> 完整的走查记录在 `xraytun-next/docs/ux/USER-JOURNEY-REAL-PERSON.md`。

## 这一版新增/修好的

### 1. 订阅：从「不做」变成「做了」

- **设置 → 订阅**里现在可以直接填订阅 URL 添加，每条订阅有「刷新」。
  入口仍然由 daemon 的能力表门控（`subscription_fetch` 没宣告就不渲染，不是灰按钮）。
- 拉取由 daemon 执行，用的是 **系统自带的 `/usr/bin/curl`**（绝对路径 + argv，永不经过 shell），
  **没有新增任何依赖**：这是老版 v0.9.2 对同一个功能的结论，本轮沿用。
- 订阅节点会**落盘**（`subscriptions.json`），重启不需要联网也有节点。
- **失败不静默**：加不上就当场报错；刷新失败既写进那条订阅的「上次错误」（下次打开还看得到），
  也当场告诉你。本地文件订阅（`--subscription-file`）不归「刷新」管，点它会明确说不支持这样刷。
- **令牌不进日志**：URL 里的令牌只存在本地状态文件（权限 0600）与界面上；
  日志与错误里只出现 `scheme://host/…`（连 `user:token@host` 这种写法也会被剥成 host）。

### 2. 命令行也能做同样的事（无头等价入口）

- `xt-cli add-subscription <url>` / `refresh-subscription <id>`：以前固定报「本版本不提供」，
  现在**真的连 daemon 发请求**。
- `xt-cli import-nodes <原文>`：把订阅原文/分享链接从管道喂进去（传 `-` 从 stdin 读）。

### 3. 真人走查发现的三处「看得见，但不告诉你去哪」

| 症状 | 现在 |
| --- | --- |
| 节点目录里有节点、但还没选节点时，大按钮是灰的、只写「未选择节点」 | 按钮变成可点的**「选择节点」**，点了跳到节点页；说明里逐字写清「在节点页点某一行的『选为当前节点』」 |
| 在设置页最下面添加订阅失败，错误提示却写在页面最顶上（中间隔着好几张卡） | 错误提示渲染在**订阅卡片里**，就在你点的地方 |
| 节点页没说「手里只有订阅链接怎么办」 | `subscription_fetch` 已宣告时，导入区明说「到『设置 → 订阅』填 URL」 |

### 4. 安全

- daemon 的 AF_UNIX socket 绑定后会把权限**收紧到 0600**（这条连接上会回传含令牌的订阅 URL）。
  收紧失败时照常启动并告警 —— 不让一个 chmod 把 daemon 挡在门外。

## 仍然**没有**做到的（不许含糊）

- **TUN 真机接管没有验收过**：helper 安装、授权弹窗、`utun` 接管、路由与 DNS 提交，
  这几步**只有在你自己的 Mac 上装一次才能验**（CI 上装 launchd daemon 不可靠）。
  所以本版能说的是「通路已宣告 + 界面按能力门控 + 失败如实报错」，**不是「能翻墙了」**。
- 本版**不是公证版**（无 Apple Developer ID，S5 未做），Gatekeeper 的拦截行为以你真机为准。
- 订阅正文的大小限制是**两道**（`--max-filesize` 5 MiB + 长度复查 + 20 秒超时）：
  源站用 chunked 且不给长度时，curl 仍会把正文读进内存 —— 对「用户自己填的 URL」这个模型够用，
  但不构成「内存上限」的证明。
- 订阅**没有定时自动刷新**（只有你点「刷新」时才拉）。「贴一条订阅 URL 就自动更新」这句话仍然不成立。

## 怎么验（给真人的最短路径）

1. 装本版（DMG 或 zip），打开 App。
2. **节点**页：把机场给你的订阅原文或一串分享链接粘进输入框，点「导入」；
   或者去**设置 → 订阅**填订阅 URL，点「添加订阅」。
3. 回到**节点**页，在你要用的那一行点**「选为当前节点」**。
4. 回**仪表板**，按那个大的**「启动」**按钮。
   第一次会让你装特权助手（需要一次管理员授权）—— 这是 TUN 模式的硬前提。
5. 想收工时按「停止」，再到**设置**里把它**卸载**（卸载会删掉三样东西，界面上写清了）。

任何一步失败，界面都会给出具体的错误码与原因；如果哪一步「点了没反应」或者文案在骗人，
那都是 bug —— 记录在走查文档里就行。
