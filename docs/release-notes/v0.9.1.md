## 给用户的动作：**必须换成这个新 App**；**不需要重装特权助手**；**审计同步默认关闭**

依据（可复算）：

```bash
git diff --stat v0.9.0..v0.9.1 -- crates/xt-helper crates/xt-tun crates/xt-proto
# → 三个 helper 侧 crate 零改动
grep -n 'PROTOCOL_VERSION' crates/xt-proto/src/lib.rs     # 4（与 v0.9.0 相同，未变）
```

协议号未变、helper 侧可观察行为未变 ⇒ 装不装助手都能用新 App。
本版改动集中在 `apps/ui`、`apps/desktop`、`crates/xt-intent`、`crates/xt-core`（位置缓存）与站点。

### 1. 想让「每天自动上传审计」跑起来，要你自己开一次

这是本版唯一一个**需要你动手才生效**的新功能，而且**默认是关的**（关着的时候一个请求都不发）：

1. 装好新 App → 设置 → **系统与助手 → 审计同步** → 打开开关；
2. 粘贴上传 token（它只在你那台机器上：`<workspace>/.secrets/audit-upload-token`）；
3. 完成。之后 App 每 30 分钟检查一次，把**已经过完的 UTC 天**加密上传，关机错过的天会在下次启动补齐。

它传的是**端到端加密的密文**：密钥在你设备上，服务端只能看到「某个随机设备号在某天有几百行」，
**看不到任何域名**。App 里有一处「查看将要上传的内容」可以让你在开启之前先看清会传什么（本机数据、不联网）。
不想传就关掉开关；已经传过的可以「撤回全部已上传」。

### 2. 诚实边界

* **真机 macOS 行为未验证**：定时器在休眠 / 退出 / 升级里的行为、以及界面文案在真机上的观感，
  开发机不是 macOS ⇒ 这一条只到「单测 + 编译 + CI」级别，**没有真机证据**。
* 本版新增的审计端点**已真实部署并跑过一次真实客户端端到端**（密文落盘、取回检查无明文残留、
  撤回清理）；证据与「哪些没验证」写在 `docs/verification/AUDIT-SYNC-VERIFY.md`。
* 位置查询会把**你的公网 IP** 发给多个第三方坐标源（这是它本来就得做的事）；
  本版把它做成**按公网 IP 缓存**，所以「同一个 IP 不会反复查」，并且界面上标注了来源。

## 这一版改的是「少查、少算、少藏」

一句话：

> **位置只在公网 IP 变的时候才查 · 判决在父域已经判过时不再问模型 · 审计能离线出报告、也能自动送出去**

### 1. 「地球仪」改名「位置」，并且按公网 IP 缓存

「地球仪」是个视觉名字，而这一页回答的是「我在哪、出口在哪」——所以侧栏与文档统一改叫**「位置」**
（页面 id 仍是 `globe`，老链接不受影响）。

更重要的是它以前**每次进页面都可能重新查一遍**。现在：

* 位置缓存**以公网 IP 为键**（IPv6 按 `/64` 归一）——同一个 IP 不会重复查；
* 缓存条目有 TTL，失败有冷却（`LOCATION_PROBE_TTL_S=120`、`LOCATION_FAIL_COOLDOWN_S=60`、LRU 24 条）；
* 探测失败时**给标注过的旧数据**（`stale`），并写明「暂时无法确认公网 IP 是否变化」——
  绝不把「没测到」说成「没变化」；
* 坐标源从 4 个扩到 **8 个**（`ipwho.is` / `ip-api.com` / `ipinfo.io` / `ifconfig.co` /
  `ipwhois.app` / `geoiplookup.io` / `freeipapi.com` / `api.ipquery.io`），另有 4 个 IP-only 源
  （`ipify` / `1.1.1.1 cdn-cgi/trace` / `bigdatacloud` / `country.is`）。

### 2. 判决缓存命中率：父域判过的，子域不再问模型

以前 `a.b.example.com` 与 `example.com` 是两个完全独立的判决 —— 每次都要重新花钱问一遍。
现在引入**父域（eTLD+1）继承**：

* 自包含的多级后缀表（`MULTI_LABEL_SUFFIXES`）+ `registrable_domain()`，不依赖外部 PSL 运行时；
* 继承来的判决有**自己的上限**（`INHERIT_TTL_CAP_SECS`，7 天）与来源标记（`inherited_from`）；
* 引擎多出三个计数器：`cache_misses` / `cache_inherited` / `cooldown_skipped`；
* 网关失败进 **60 秒冷却**，冷却期内不重复打同一个坏掉的网关（也**不伪造判决**）。

界面上「判决缓存」那一行显示命中率。**命中率的算法是 hits / (hits + misses)** ——
`cache_inherited` 是 hits 的**子集**，不能加两次（第一版就是加错了、把 44% 显示成 56%，已修并配了反例测试）。

### 3. 审计：能离线出报告，也能每天自动送出去

* **离线报告 + CLI**（`crates/xt-intent/examples/intent_audit.rs`）：
  `report` 把 `intent-audit.jsonl` 聚合成**能拿来做决定**的东西 ——
  每天 / 每域 / 每模型的汇总、缓存命中率、演练比例、**新域/天 的均值与 p95**、
  「该固化成静态规则」的候选（固化后不再问模型）、「该看阈值」的候选，以及 Token 与 Neuron 成本账。
  `report` 与 `bundle` **不联网**，也不需要密钥。
* **自动同步**（默认关闭）：按 UTC 天组包 → 在设备上加密（ChaCha20-Poly1305，
  明文头 device/day/rows 一起进认证范围）→ `POST /api/audit`。
  R2 的 key 由「设备号 + 天」决定 ⇒ **重传只覆盖，永远不可能重复**；
  只传**已经过完的天**，关机期间错过的会在下次启动补齐（退避封顶 6 小时）；
  **偏好文件坏掉按关闭处理**（一个读不懂的配置绝不能被读成「用户同意上传」）；
  「记录外发内容」里的 `context_sent` 在同步时**一律剥掉**（有测试钉住）。

### 4. 顺手修掉的

* 判定缓存界面的命中率公式（见上，重复计数）；新增反例测试。
* 分节数不变量、命令契约哨兵（50 → 57）随新增的 7 条 `audit_sync_*` 命令同步更新。
