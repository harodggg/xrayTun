# NON-GOALS · 不做什么，以及我们因此放弃的收益

> 作者：product · 配套 `SCOPE.md`（做什么）与 `ACCEPTANCE.md`（怎么验）
> **本文件的第一要求是诚实**：每一项不做，都必须写清「用户会因此失去什么」，
> 包括**用户确实用过、或确实会想念**的东西。只写「不做」不写代价，等于把成本藏起来。
>
> 证据口径同 `SCOPE.md §1`：`[证据]` 可复核 / `[裁决]` 用户或 lead 明确记录 / `[推断]` / `[假设·未验证]`。

## 0. 怎么读

每条「不做」有三段：**为什么不做**（证据 + 推理）、**用户看到什么 / 失去什么**、
**什么时候才该做**。§2 是旧仓库优化分析里**已被证明「没人用」或「用复杂度换来更少东西」**的清单——
本轮不重建它们即等于继承那些结论。§3 集中写代价（「我们放弃的收益」）。§4 是**禁止发明**清单。
§5 是重新引入的门槛。§6 是未决项（未决 ≠ 已做）。

## 1. 本轮明确不做

### 1.1 macOS TUN

* **为什么不做**：TUN 需要 `RunMode::Tun` + 特权 helper + 路由/DNS 接管；契约冻结 I5 写明「helper 本轮**不实现**，因此任何『TUN 已工作』的说法都是假话」；§8 把 TUN 列为明确不做。而且**验证手段不存在**：开发机不是 macOS（`HANDOFF.md §4`「本机没有 cargo/gcc/docker」，真机验收只有用户能做，§2.2「开发机不是 macOS ⇒ 本版 TUN/切换的真实行为**没有**证据」）。
* **旧仓库的现场还在**：`xray-tun/docs/incidents/OPEN-FINDINGS.md` F-1（`127/8` 回环被指进隧道，`route -n get 127.0.0.2 → utun6`，用户机器不重启**不会自愈**）、F-4（换节点后旧节点的旁路 `/32` 残留）。在**一个已经发布、有真机用户**的版本上，这类问题都还开着；在重写里先做 TUN 等于把无法验证的风险再复制一遍。
* **用户会看到 / 失去什么**：只能用一个本机 SOCKS 入口——**每个 App 要单独配代理**，没有「全机自动走节点」。对只浏览器上网的用户影响小，对期望「系统级代理」的用户是**功能缺失**。这是本轮最大的一块功能放弃。
* **什么时候才该做**：有 macOS 真机、有 helper、且能对「建卡 / 路由 / DNS / 崩溃回滚」给出真机证据之后。

### 1.2 特权 helper

* **为什么不做**：它只做一件事——改系统网络状态；一旦做了就必须同时做**会话快照 + 启动回滚 + 崩溃后还原**。旧仓库自己把这一层称为「本项目**最不能省**的一层复杂度」（`IA-AND-OVERBUILD.md §4.2`：「崩溃/断电/被 kill -9 之后网络还能回来」）。本轮没有 TUN，helper 也就没有服务对象。
* **用户会看到 / 失去什么**：没有特权组件 ⇒ 没有系统级网络改动，也就**没有「改坏系统网络」的风险**（这是收益）；代价是与 1.1 相同的功能缺失——以及**失去崩溃后自动还原系统网络的安全网**（因为这个安全网只为 helper 的改动存在）。
* **什么时候才该做**：与 TUN 同批；且必须带真实回滚验证，不许只有设计文档。

### 1.3 审计上传

* **为什么不做**：契约冻结 §8 明确不做。旧仓库 v0.9.1 做过完整实现（`docs/design/AUDIT-SYNC.md`、`docs/verification/AUDIT-SYNC-VERIFY.md`，接收端 Cloudflare Worker + R2 已上线），`HANDOFF.md §1.1` 记录它**默认关闭**、开了要填 token。把「端到端加密客户端 + 定时器 + 上传 token + 服务端」搬进重写，会显著扩大依赖面与验证面，而它**不在 proxy 纵切面的关键路径上**。
* **用户会看到 / 失去什么**：失去「自动、加密地把问题报告送到开发者」的能力。出问题时用户只能：自己描述现象 + 手动贴日志。旧版默认关闭这一点说明它**不是刚需**，但「出问题后开发者能不能拿到现场」这件事会变差。
* **什么时候才该做**：用户明确要求一条支持通道，且隐私模型（端到端加密、撤回、默认关闭）被重新验证之后。

### 1.4 地理 / 拓扑可视化

* **为什么不做**：契约冻结 §8 明确不做。更根本的是**数据源不存在**：旧仓库的「最近连接」来自访问日志、「某个地址走哪条路」来自运行配置与规则链、「位置」来自公网 IP 查询（`xray-tun/docs/release-notes/v0.9.1.md §1`），这些在 proxy 纵切面里都还没有。先画图等于**先做视觉、后做数据**——旧仓库的实测教训正是这个：拓扑页 1890 px（2.97 屏）里**装饰性流图占首屏 99%，三块真实数据落在第 1.2 / 1.5 / 2.3 屏**（`xray-tun/docs/product/PRD.md §2`、`IA-AND-OVERBUILD.md §2.2`）。
* **用户会看到 / 失去什么**：没有流向图，也没有地球仪。**诚实地说：用户确实用过它**——PRD §3.3 决策 C 记录「用户刚要求过放大倍数，说明他在用」。所以这不是删掉一个没人用的装饰，而是**砍掉一个用户看得见的功能**，代价必须写在明面上。
* **什么时候才该做**：proxy 主通路真机验证通过、日志/规则/位置三类数据源存在之后；并且不许再把装饰放在真实数据前面。

### 1.5 自动重连 / 回落 / 重试

* **为什么不做**：I2（没有回落）是**可机器检查**的不变量：`ErrorCode` 是封闭枚举且**没有** `Retry`/`Fallback`/`Degraded` 成员（`crates/xt-contract/src/error.rs:8-9` 注释与 `:10-33` 定义），`guard.sh` 扫 `fallback`/`retry`/`backoff` 标识符。用户的裁决也已经写进产品：`xray-tun/docs/release-notes/v0.9.2.md §1` 引用用户原话「自动重连和看门狗本来就没什么用，解决不了网络问题，**每一次都是我去连**」，并给出三层理由（探不到 ≠ 连不上；会把「连不上」变成一次你没同意的操作；判定等待落在用户操作路径上）。v0.9.2 据此删掉了这些机制（净删 5455 行）。
* **用户会看到 / 失去什么**：换网（咖啡厅→家）、合盖唤醒、节点临时抖动之后，**隧道不会自愈**——失败就是失败，用户必须自己点重连或换节点。换来的东西是**明确性**：现在出口永远是他选的那台，不会有人替他偷偷操作。代价是**每次断网都要手动点一下**，这一点不能含糊。
* **什么时候才该做**：默认永不。若将来要有，必须先在 `ErrorCode` 里加成员并过评审（`error.rs:8-9` 明说「加成员要过评审」），而且不许重新引入「自动换到另一个节点」这类改变出口归属的行为。

### 1.6 订阅之外的账号体系

* **为什么不做**：契约里**没有任何**账号 / 用户 / 设备身份类型（`model.rs` 全文只有 `NodeId`、`SubscriptionId`、`DaemonHello.pid` 等本机标识）；也无证据表明用户有多设备同步需求（`[假设·未验证]`，没有相关记录）。
* **用户会看到 / 失去什么**：没有登录、没有跨设备同步的节点与设置。**每台机器都要重新配一次**；设备丢了也没有「从账号恢复」这条路。代价是真实的，只是没有证据说用户现在需要它。
* **什么时候才该做**：用户明确有多设备需求时。

### 1.7 订阅远端拉取（http/https）

* **为什么不做**：`[裁决]` lead 2026-09-29（team-message-5f45ef69）：不在纵切面的关键路径上，且引入 TLS 客户端会扩大依赖与验证面。本轮 `xt-subs` 只实现「解析订阅原文」，节点来源是本地 `--subscription-file`（默认 `$state_dir/subscription.txt`）。
* **本轮做的是它的另一半**（别把它读成「订阅整块不做」）：本地解析**做**并宣告 `Capability::Subscriptions`；拉取侧**不宣告** `Capability::SubscriptionFetch`（lead 2026-09-29 拆分裁定）。界面订阅区块**只读**：`id` / `url` / `node_count` / `fetched_at_ms` / `last_error`，**没有「添加订阅 / 刷新」入口**；`AddSubscription` / `RefreshSubscription` 属拉取语义 ⇒ daemon 返回 `Unsupported`（该错误码**已落地**：`error.rs:33/52/105-106`；能力宣告与使用纪律见契约冻结 §3.1）。
* **用户会看到 / 失去什么**：**失去「贴一条订阅 URL 就自动更新」**。用户必须自己把订阅文本保存到 `$state_dir/subscription.txt`；服务端换了线路，App 不会自己发现。对习惯「订阅地址=自动更新」的用户，这是明确的退步。
* **什么时候才该做**：主通路稳定、且愿意承担 TLS 客户端（依赖 + 证书/超时/错误分类）之后。

### 1.8 延迟探测是「条件交付」而不是「不做」

* **口径**（`[裁决]` lead 2026-09-29）：probe **做成才做**——只有在 `DaemonHello.capabilities` 里宣告 `Capability::Probe` 之后，界面才能有探测入口；没做成就不宣告，**界面里连入口都不存在**（不是灰按钮、不是「即将推出」）。
* **为什么这样处理**：契约冻结 §7 禁止假控件；界面陈述的能力必须是真的（I3）。预先把「测延迟」写进产品文档、而实现没做，就是发明功能。
* **用户会看到 / 失去什么**：如果本轮没做，用户**无法在选节点前对比延迟**，只能连上才知道快不快。这是 T3（换节点）体验上的实打实损失，必须如实写在界面上没有这个入口，而不是假装有。

### 2.1 顺带记下：旧仓库判定「不该简化」的东西（本轮同样不为了简洁去删）

旧仓库的审计结论里有一批「看起来复杂、其实是正确性」的东西——`CP §3` 十条、`IA §4` 七条。重写时**最容易犯的错**是以「新代码更简洁」为名把它们丢掉。本轮明确**不因简洁而放弃**下列设计约束（它们在本轮以契约/状态机形式存在）：

* 「默认路由已接管但数据面没起来」的流量黑洞窗口 → 契约冻结 §4：`stage == Connected` ⟺ 数据面**已被证明可连**（proxy：SOCKS 端口接受连接）。
* 「失败之后界面说成功」→ I3 + `last_error` 不被后续成功替换。
* 「退出/崩溃后系统网络状态留在坏状态」→ 本轮因为没有 helper 而不存在；**若将来引入 helper，`restore_stale` 这类机制必须一起引入，不许省**（IA §4.2、CP §3 第 9 条）。
* 「五档状态色 / 绿色只属于 on」等旧 UI 红线 → 归 ux/design，本轮至少不引入「靠颜色单独表意」的新界面。

## 3. 我们放弃的收益（诚实清单）

> 这一节存在的唯一目的：**让代价可见**。每一项都写「谁失去了什么、多久失去一次、有没有别的路」。

| # | 放弃的收益 | 用户具体失去什么 | 有没有替代路 | 影响面 |
| --- | --- | --- | --- | --- |
| R1 | 全机自动代理（TUN） | 不能「打开 App 就所有程序走节点」；每个 App 要自己配 SOCKS | 手动配每个 App；或用户自己做系统级转发（我们不做、也不承诺） | **大**：这是「代理客户端」的核心价值之一 |
| R2 | 系统网络状态的崩溃还原（helper 快照） | 失去「崩溃/断电后网络自动回来」的安全网 | 无（本轮不改系统网络，所以暂时也没有这种坏状态） | 中：**只是因为我们没做 TUN/helper 才不痛**，不是它没价值 |
| R3 | 审计自动上传 | 出问题不能一键送现场；只能手动描述 + 贴日志 | 用户手动导出/复制日志（若本轮做了日志页） | 中：仅影响排障效率 |
| R4 | 流向图 / 地球仪 | 看不到「流量去了哪」的可视化；**用户确实用过**（PRD §3.3 决策 C） | 无 | 中：可见功能退步 |
| R5 | 延迟探测入口（若条件交付未达成） | 选节点前无法对比延迟，只能连上才知道 | 无（本轮不宣告 = 界面无入口） | 中：直接影响 T3 体验 |
| R6 | 自动重连 / 自愈 | **换网、合盖唤醒、节点抖动后必须手动重连**；失败就是失败 | 用户手动点「连接」或换节点 | **大**：每一次网络变化都要用户出手（用户已明确接受，但成本真实存在） |
| R7 | 失败自动换节点（回落） | 连不上时不会自动换到能用的节点；用户得自己找 | 用户自己在节点列表里换（前提：有节点来源） | 中：换来「出口永远是你选的那台」 |
| R8 | 订阅 URL 自动更新 | 不能贴一条 URL 就自动更新；服务端换线路后 App 不会自己发现 | 手动把订阅文本落到 `$state_dir/subscription.txt` | **大**：对订阅用户是日常退步 |
| R9 | 跨设备同步（账号） | 换机器/重装要重新配订阅与设置 | 无（本机文件可手工拷） | 小到中：取决于用户设备数（`[假设·未验证]`） |
| R10 | 旧版全部既有能力的**归零**（重写的固有代价） | 新仓库要重新建 TUN、helper、审计、位置、分流、拓扑、日志页、订阅页、开机自启、自更新、托盘等——**本轮用户看到的是「功能比旧版少」** | 无（只能靠时间逐轮补回） | **大**：这是重写最诚实、也最容易被隐瞒的代价 |
| R11 | 浅色主题 / 国际化 / 流量曲线 | 失去少数审美与语言需求的满足 | 无 | 小：与用户提出的痛点零重叠（PRD §4） |

**一句总账**：本轮交付的是一个**能真实跑通、每句话都有出处**的 proxy 最小纵切面；代价是功能总量**倒退**（R10），并且其中 R1/R6/R8 是用户每天都会碰到的。这个账必须由 lead 在对外口径里如实表达，不许用「v1.0.0」这个版本号暗示功能完整。

## 5. 重新引入的门槛（防止「以后顺手加回来」）

1. **自动换路类行为**（重试/回落/降级/自愈）：必须先在 `ErrorCode` 加成员并过评审——`error.rs:8-9` 把这件事刻意做成「加成员要过评审」，`guard.sh` 扫 `fallback`/`retry`/`backoff` 标识符。加回来必须先改契约、再改代码、最后改本文档。
2. **新的进程边界 / 微服务**：必须证明收益 > 代价（契约冻结 §1 已给本轮唯一一处边界的四条理由）；跨 TCP 的服务要解释为什么不是进程内模块。
3. **兼容旧版本 / 分支式演进**：直接拒绝——`PROTOCOL_VERSION` 不符即 `invalid_request` 并关闭连接（`lib.rs:23-25`、契约冻结 §3），不许写「尽量兼容」。
4. **任何新界面能力**：必须在 `DaemonHello.capabilities` 里先有可宣告的能力；界面只渲染已宣告项（未实现 = 入口不存在，不是灰按钮）。本轮的正例就是订阅：`Subscriptions`（本地解析）宣告、`SubscriptionFetch`（远端拉取）不宣告 ⇒ 界面没有「添加/刷新」入口。
5. **任何「未知显示成 0/空」的字段**：直接拒绝——没有数据就是 `None`（`model.rs:3-5`）。
