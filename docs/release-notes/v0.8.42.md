## 这一版修的是：**你自己加的拦截规则，以前一次都不会生效**

现场可复现的 bug：在「自定义规则」里加一条 `拦截`（例如 `badjs.weixinbridge.com`），
**它永远不命中** —— 只要那个域名命中任何预设 `direct`（例如 `geosite:CN`）。

根因：规则表把**用户自定义规则排在了预设之后**，而 `preset-cn-domain` 这类 direct 规则先命中，
排在后面的 `block` 连看都看不到。界面允许你创建一条注定无效的规则，**且没有任何提示**。

修好后的顺序（判据：**用户显式 > 推断 > 预设**；`preset-private` 永远第一，不可覆盖）：

```
preset-private → 用户放行纠正 → 用户自定义规则 → 推断出的意图拦截 → MITM steer
→ preset-ads → preset-cn-domain → preset-cn-ip → 兜底
```

**这一版之后你才真正能用"自定义规则"拦广告投放端**：日志里 `badjs.weixinbridge.com` 这类
微信广告桥此前命中 `preset-cn-domain → direct`（= 没拦），现在会按你的规则走 `block`。

## 怎么用（三分钟）

1. 「路由/规则」页 → 自定义规则 → 添加，域名填 `badjs.weixinbridge.com`，动作选**拦截**；
2. 保存后**重连一次核心**（规则在核心启动时下发；本版不改这一点）；
3. 打开它去复现那个广告位：**变空白 = 生效**；没变 = 投放端换了通道，我们再按同一套流程
   （从日志捞候选域名 → 加规则 → 实测）迭代。

> 诚实边界：**同域/一方渲染**的广告（平台自己的接口返回、自己画的卡片、素材与正文同 CDN）
> 域名层拦不到 —— 拦它等于把正文图片一起拦掉。这是层次问题，不是实现不足。
