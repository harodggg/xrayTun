## 1. 主任务：`scripts/check-css-tokens.py` + `check.sh` 加一步

### 1.1 为什么这道检查必须存在

这是本项目**第三次**「**静默失效的声明**」：

| # | 形态 | 症状 | 谁发现的 |
|---|---|---|---|
| 1 | `--line` 从未定义（无兜底） | 拓扑那条分隔线**从未渲染** | task-12 / `e7ed509` |
| 2 | `xattr -dr` 必然失败 + `2>/dev/null` 吞掉 | 隔离标记没去掉，更新后被 Gatekeeper 拦 | task-17 的线索 / task-46 |
| 3 | `--border-interactive` 在应用 bundle 里未定义 | `border-color` 落到 `currentColor` → **近白描边** | task-57 / `b91ffb1` |

共同点：**浏览器不报错、样式表不报错、`tsc` 不报错**。只有人拿放大镜量计算样式才看得出来。
（CSS 规范叫 *invalid at computed-value time*：`var()` 引用一个没有值的自定义属性且**没有兜底**时，
整条声明在计算值阶段失效 —— 简写属性整条被丢弃，`border-color` 这类长写落到 initial，
而 `border-color` 的 initial 是 **`currentColor`**。所以症状各不相同：**有的什么都没发生，有的变出个你没要的颜色**。）

### 1.2 判据：**按 bundle** 分作用域（这是本检查最关键的设计）

**`--border-interactive` 在全仓库里「搜得到」** —— 它在 `site/assets/site.css:48` 有定义，那是**官网**的 token 表。
但应用不加载那个文件，所以**对应用而言它就是未定义的**。

⇒ 用一个「全仓库定义集合」去判，**这条永远测不出来**。
**我第一版原型就踩了这个坑**：用全局集合跑，结论是「0 违规」，而当时真 bug 就在文件里。

所以脚本按 bundle 分别判定，每个 bundle 的引用只能由**同一个 bundle 内**的定义满足：

| bundle | 提供定义 | 视为引用 | 排除 |
|---|---|---|---|
| 应用 UI | `apps/ui/src/**/*.css` | 同上的 css + `**/*.tsx` + `**/*.ts` | `**/*.test.tsx`、`**/*.test.ts` |
| 官网 | `site/assets/**/*.css` | 同上的 css | — |

* **为什么把 TSX 也算引用**：内联样式 `style={{ color: "var(--danger)" }}` 是同一种失败模式，
  而它引用的 token 只能由本 bundle 的 CSS 提供。
* **为什么排除 `*.test.*`**：测试里会写 `var\((--[\w-]+)\)` 这类**正则/字符串**去解析样式表，
  那不是真引用，算进来就是误报（我自己的 `topbarStatus.test.tsx` 就是这种）。
* **为什么排除 `dist/**`**：构建产物不是源。
* **兜底语法**：`var(--x, fallback)` 是**合法**的，不算违规 —— 本项目 `--panel` 就是这种（刻意保留）。
  判据不能用「第一个逗号」：`var(--x, rgb(1,2,3))` 的兜底里也有逗号。
  按 CSS 语法，名字后面紧跟的那个字符就够了（`var( <name> , <value>? )`）。
* **先剥注释再扫**，且**保留行号**（把注释内容替换成等量空白）—— 报错要给人 `文件:行`，差几行就没人能一眼找到。

### 1.6 类名方向：**我没有把它加进脚本**（附理由与证据）

`var(--x)` 之外，同一族还有「**TSX 用了某个类名、CSS 里没有定义**」这个方向

**原型判据**：把 TSX 里**静态字符串** `className="…"` 与 `classList.add("…")` 里的 token，
拿去和 CSS 里出现过的类名对比。当前仓库跑出来 **2 个**「用了但没有定义」：

| 类名 | 用处 | 真实情况 |
|---|---|---|
| `logs__banner` | `Logs.tsx`：`className="banner banner--error logs__banner"` | **合法**：样式由 `.banner` + `.banner--error` 提供；真正有样式的是它的子元素 `.logs__banner-text`（CSS 里有）。`.logs__banner` 就是个无语义负担的钩子 |
| `usage__pct` | `Subscriptions.tsx` 两处 | **合法**：只有 `--warn` / `--danger` 两个修饰符需要定义（改颜色），基类继承 `.usage__text` 的颜色即可 |

⇒ **2 个发现全是假阳性（0% 准确率）**。根因是**判据不对称**：

* `var(--x)` **没有兜底**时，CSS 规范规定这条声明**必然失效** ⇒ 「引用了但没定义」是**可证的真缺陷**；
* 一个类名出现在 `className` 里 **不构成任何「应该有样式」的承诺** ——
  纯语义钩子、只靠修饰符的写法都是**合法的**，而且很常见。

**并且它还会漏报**：动态拼接的类名（`highway__lane-label--${o.kind}`、`dot--${tone}`）在静态扫描里根本看不见。
（反向的「CSS 类名没人用」PM 也统计过：19 个里 16 个是动态拼接 —— 同一个机制。）

**决定**：**不加**。按你的要求「不许为了覆盖率交一个会误报的检查」。
*代价说清楚*：`.row--between` 那一类**不会被这道检查自动拦住**，只能靠人读代码或看界面（我就是看界面看出来的）。
要覆盖它需要一个**完全不同的判据**（例如「`x x--y` 同时出现时要求 `x` 有基类规则」），
但那个判据在当前代码里**也会对 `.usage__pct` 误报** —— 所以现在没有可靠的静态判据。

## 4. `prefers-reduced-motion`：补上 `spin` 与 `set-target-flash`

### 4.1 改了什么

原来只覆盖 `.flow__highlight`（1/3）。现在同一个媒体查询里多了两条：

* **`.spin { animation: none }`** —— 它是**无限循环**动画，对动效敏感用户是**持续**干扰。
  关掉后仍是「带强调色缺口的圆环」（`.spin` 自带 `border-top-color: var(--accent)`），
  **不会变空白** —— 变空白会被读成「卡死」。
* **`.set__sec.is-target { animation: none; box-shadow: inset 2px 0 0 var(--accent) }`** ——
  这是深链/跨页落到某个分节时的 2.4s 闪烁，**由导航触发、用户无法预期**。
  **只写 `animation: none` 会把「就是这里」的落点提示整个弄没**，所以换成**静态**左侧强调条：
  `is-target` 由 JS 在 **2400ms** 后移除（与 2.4s 动画等长，见 `Settings.tsx`），
  静态条持续时间与原闪烁一致 —— **保留提示，去掉闪烁**。

### 4.2 零观感变化怎么证明（你要求的那一条）
