> ## ⚠️ 给用户的动作：**本版必须重新安装特权助手**
>
> 依据（可复算）：
>
> * `crates/xt-proto` 的 `PROTOCOL_VERSION` **1 → 2**（新增 `InstallTrustAnchor` / `RemoveTrustAnchor`）；
> * `crates/xt-helper/src/server.rs` 新增这两个请求的处理 —— 它会往**系统钥匙串**装/卸我们的本地根证书；
> * 所以装着旧助手的机器上，设置页会报**「助手版本不匹配」**，TUN 与 MITM 都无法工作。
>
> 在 App 里点一次「重新安装助手」（或先卸载再安装）即可；装完不需要再做别的。

## 这一版给你什么

### 意图过滤（默认**关闭**，要你自己打开）

* 复用 Jev / System One 的**类型化判定**，在**域名/端点层**判断"这是不是投放/追踪基础设施"，
  命中就交给 Xray 的 blackhole —— **TCP 与 UDP 都生效**，UDP-only 的拦截是**静默丢弃**。
* **默认关闭 + 演练模式**：判决照做、审计照写，但不下发拦截规则。
* **诚实的边界**（本机真实语料实测）：免密钥档的模型**没有发现任何静态名单之外的新广告域**
  （无标注桶 0/96，两次独立运行），已知广告域召回只有 **1/3 ~ 2/3**。
  所以这一版**不把它说成"打开就能过滤广告"**；要它有用，需要换更强的模型
  （TypeSafe 等预设需要 Key），或改问题/提示词后**重新量**。
* 界面：意图过滤页可以开关、看审计（每条判决的结论/原因/分数/是否真的生效）、
  放行误杀、以及决定何时把规则应用到核心（**不自动重连**，那会打断你所有连接）。

### 可选 MITM（内容级判定，默认关闭，**只对你逐个点名的域名**）

* 域名层拦不住**同域**广告（时间线里的推广条目、同页接口里的推广位），要碰内容只有拆 TLS 一条路。
* 代价与边界都写在界面上：会往**系统钥匙串**装一张本地根证书（本版**每次启动重新生成**，
  退出或下次启动的过期会话回滚会把它撤掉）；只对你点名的那几个域名拆；ALPN **只协商 http/1.1**；
  可选「响应体裁剪」（删掉 JSON 里某个布尔字段为 `true` 的条目，**默认不启用**）。
* **三道闸门**：开关 + 名单非空 / 根证书已在钥匙串 / 代理在跑。**证书没装时不会下发引导规则** ——
  否则那几个域名的 HTTPS 会撞上一张没人信的证书，那不是过滤而是把网站搞坏。
* 已知限制：**WebSocket 端点会收到 501**（别放进名单）；非 443 的 HTTPS 服务需要调端口旋钮。

### TUN 连接更稳：这一版修了三处真实现场

1. **接管默认路由前的门禁失败会重试一次**（只重试失败的目标）—— 一次瞬时抖动不再打掉整次启动；
2. **按产品真实数据路径探测**：TUN 模式下域名由**核心**解析、节点只看到 IP，
   所以不再要求"节点解析域名"（那会把 DNS 受限、但实际可用的节点拦在门外）；
3. 门禁失败的**归因更正**：域名目标是**节点侧**解析的，不该说成"本机网络/DNS 被干扰"
   （顺着旧文案去改本机 DNS 是徒劳的）。

### 其它

* UDP-only 的拦截改为**真正静默**（新增 `block-silent` 出站；`response.type: none`）；
* 站点 JSON-LD 一致性检查接进门禁（`gen-site-jsonld.py check`），并修掉美颜页登记值漂移；
* TUN 配置形状新增真实核心验收（纯 TUN / +意图规则 / +MITM 引导三个组合都由核心自检通过）。
