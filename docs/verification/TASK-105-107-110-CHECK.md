## 2. **「多对象行是否真的不丢」→ 不丢（且三类分别报数）**

```
$ cargo test -p xt-core --test log_readside_check -- --nocapture        # HEAD
summary(): 读取：1 个文件 / 4 行（空行 1）/ 3 条记录；多对象行 1、**无法解析的行 2**、因 limit 截断 0
lines=4 empty=1 records=3 multi=1 malformed=2 bad=["app.jsonl:3", "app.jsonl:4"]
test read_side_keeps_multi_object_records_and_reports_categories ... ok
test clean_log_reports_no_loss ... ok
```
人造日志四行：① **一行两个对象**（`app` 的「隧道已自动恢复」+ `core` 的启动横幅）② 正常行 ③ **真截断**（`…"mess`）④ **完全非 JSON**，末尾一个空行。断言全部通过：
* `records = 3`（两对象行贡献 **2** + 正常行 1）⇒ 一行多对象**真的全部读出**；
* `multi_object_lines = 1`、`malformed_lines = 2`（截断 + 非 JSON）、`empty_lines = 1`（空行单列，**不算坏行**）；
* **两对象行里的 app 事件读到 1 条、core 横幅也读到 1 条**（这正是旧实现整行丢掉的）；
* `bad_lines = ["app.jsonl:3", "app.jsonl:4"]` ⇒ 坏行给了**可定位的样本**（不给样本的「有 N 行坏了」没法排查）。

## 3. 丢行**可见**（`task-110`）：有第二条出口，且措辞不掩饰

`crates/xt-core/src/store.rs` 的 `TailLogStats` 本身就把三类分开报：
`records` / `multi_object_lines` / `malformed_lines` / `truncated`（**明确区分「解析不了」与「因 limit 没列出」**）+ `has_loss()` + `summary()`。

用户可见出口（`apps/desktop/src/commands/diagnostics.rs`，**逐字抄**）：
```
loss_warning():   「读取日志时发现 {N} 行无法解析，这些行的内容读不出来（具体位置：…）；
                   其余日志不受影响，已继续读出（**这不是正常情况**）」
read_stats_line(): 「读取 N 个日志文件」+「共 X 行 / Y 条记录」
                 + 「其中 K 行一条里含多条记录（已全部读出，**旧版本会整行丢掉**）」
                 + 「**N 行无法解析、内容读不出来**（具体位置：…）」/ 否则「0 行无法解析」
                 + 「…只列出最近 M 条（**更早的日志没丢，只是没显示**）」
```
* 它还**故意**不把「只列最近 N 条」写成「截断 N 行」——注释写明：真实日志上这一项是 35 万量级，
  写成「截断」会让用户以为丢了东西，而这行存在的意义恰恰是**分清「丢」与「没丢」**。
* 刷屏控制：`LOSS_NOTIFY` + `loss_signature`（坏行数 + 坏行样本都相同才算同一个问题）⇒ 重复出现不反复弹。
* **诚实边界**：这是**读码 + 纯函数文本**的证据；真机 UI（Tauri WebView）**无法自动化**，
  我也**没有**跑 desktop 侧的测试（要拉起整个 tauri 依赖链，构建很重）。
  行为级部分我验的是**上游**：`has_loss()`/`summary()` 与真实文件内容一致（§2 的断言）。

## 5. 口径边界与诚实清单（**哪些统计依赖日志格式、哪些测不到**）

1. **`push_log` 的行不在文件里**（内存环形缓冲）⇒ 本文所有「不丢」都只针对**已落盘**的行；
   判据是文件，不是「App 当时显示过什么」。
2. **历史重叠不会自愈**：`5874e3e` 只让**今后**不再重叠；用户机器上旧版本留下的两代文件
   （实测 ~39.9k 行重叠）**仍在原地** ⇒ `scripts/net-metrics.py` 的跨代去重**必须保留**。
3. **轮转的切点只能是 `\n`**：实现按**整行**从后往前累加（`trim_log_file` 注释写明理由），
   所以「写到一半的行」会**整行**留在它所属的那一代里——不会出现半行 JSON。
   **但我没有造这个场景**（要精确制造「写入中途被轮转」，需要并发写入，本实验是单线程顺序写）。
4. **`truncated`（因 limit 没列出）≠ `malformed`（解析不了）**：两者在 `TailLogStats` 里是两个字段，
   界面上也分开说 —— 这是 `task-110` 的关键区分，我用的是同一个结构体，没有绕过它。
5. **我只在 `xt-core` 层做行为验证**：`apps/desktop` 的 `loss_warning()` / `read_stats_line()`
   是**读码取证**（纯函数、文本已逐字抄在 §3），**没有跑** desktop 测试（构建重）、**没有真机 UI**。
6. **轮转实验写的是单对象行**（41,005 行）：多对象行对轮转的影响（整行进出、不影响 `\n` 切点）
   我是从实现注释 + §2 的读侧行为推的，**没有**造「多对象行正好落在轮转切点上」的样本。
7. **`limit` 与跨代提前退出**：本实验用 `usize::MAX`，所以没测「读到 limit 就提前退出」时
   `files_read` 的取值（结构体注释说那时不一定是 2）—— 那不在这三张卡的判据里，但**它是个口径**。

## 6. 附录：测试源码（**只在 worktree 里跑过，`main` 未新增文件**）

```rust
// crates/xt-core/tests/log_rotation_check.rs
use std::collections::HashSet;
use std::path::PathBuf;
use xt_core::store::Store;

const LOG_FILE: &str = "app.jsonl";
const LOG_BAK: &str = "app.1.jsonl";

fn tmpdir(tag: &str) -> PathBuf {
    let mut p = std::env::temp_dir();
    p.push(format!("xt-logcheck-{}-{}-{}", tag, std::process::id(),
        std::time::SystemTime::now().duration_since(std::time::UNIX_EPOCH).unwrap().as_nanos()));
    std::fs::create_dir_all(&p).expect("建临时目录");
    p
}

fn pairs(text: &str) -> Vec<(i64, String)> {
    text.lines().filter(|l| !l.trim().is_empty())
        .filter_map(|l| serde_json::from_str::<serde_json::Value>(l).ok())
        .map(|v| (v["ts_unix"].as_i64().unwrap_or(0),
                  v["message"].as_str().unwrap_or("").to_string()))
        .collect()
}

#[test]
fn rotation_two_generations_are_disjoint() {
    let dir = tmpdir("rot");
    let store = Store::new(&dir);
    let logs = store.logs_dir();
    let mut written: HashSet<(i64, String)> = HashSet::new();
    let mut i: i64 = 0;
    while !logs.join(LOG_BAK).exists() {
        let msg = format!("line-{:08}-{}", i, "x".repeat(180));
        store.append_log(&format!(
            r#"{{"ts_unix":{},"source":"core","level":"info","message":"{}"}}"#, i, msg)).unwrap();
        written.insert((i, msg));
        i += 1;
        assert!(i < 300_000, "写了 {} 行还没触发轮转（阈值变了？）", i);
    }
    let a: HashSet<_> = pairs(&std::fs::read_to_string(logs.join(LOG_FILE)).unwrap()).into_iter().collect();
    let b: HashSet<_> = pairs(&std::fs::read_to_string(logs.join(LOG_BAK)).unwrap()).into_iter().collect();
    let inter: Vec<_> = a.intersection(&b).cloned().collect();
    let missing = written.difference(&a.union(&b).cloned().collect()).count();
    println!("活动 {} 条 / 备份 {} 条 / **交集 {} 条** / 缺 {} 条", a.len(), b.len(), inter.len(), missing);
    assert_eq!(inter.len(), 0, "两代文件必须不重叠（task-105）");
    assert_eq!(missing, 0, "第一次轮转不该丢任何一条");
    let _ = std::fs::remove_dir_all(&dir);
}
```
