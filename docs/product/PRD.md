## 1. 用户要完成的四件事（Jobs）

| # | Job（他的原话） | 现在由谁承担 | 实测缺口 |
|---|---|---|---|
| J1 | 「开机后网络应该自动连上，不需要点击连接」 | 后端 `reconnect_if_needed`：24 次 × 5s ≈ **2 分钟**后台重试（`core.rs:766`、`:954`、`:956`） | **界面完全不知道这件事**：`AppSnapshot` 没有重连字段（`types.ts:312-326`），重连开始只写一行 `info` 日志（`core.rs:755`），而期间 `runtime.running=false` → 仪表盘显示「未连接」（`Dashboard.tsx:61-67`） |
| J2 | 「换网（咖啡厅→家）和熄屏唤醒后要能自己恢复」 | 后端看门狗：**10 s** 探测一轮，连续 **2** 次失败重建；唤醒后只等 1 次（`core.rs:402-500`、`:886`） | 重建前有 **10–30 s** 窗口：界面仍写着「已连接」，没有任何「正在确认/正在重建」的反馈；重建成功只写日志、**不清** `last_notice`（`core.rs:508-513`） |
| J3 | 「车要沿着线走、能看到一整个流程」「地球仪放大倍数不够」 | 拓扑流图（650 行 `Flow`）+ 地球仪 canvas | 拓扑页 2.97 屏里，**唯一有真实数据的两块在首屏之外**（见 §2）；地球仪**首屏看不到事实面板与操作提示** |
| J4 | 「明明 0 B 却有车在跑」——对假的视觉零容忍 | v0.8.25 已修 `trucksOnLane(0)=0`；v0.8.26 接入访问日志做单连接 | 仍有**一处对外承诺不实**：地球仪文案写「数量与快慢由**实测速率**决定」，代码用的是**累计字节**（`Globe.tsx:108` vs `:630`、`:647`） |

**一句话产品判断**：J1/J2 是这个产品存在的理由，而它俩是**四个 Job 里唯一在界面上没有一席之地的**。
后端把「自愈」做到了 24 次重试 + 10 s 看门狗 + 睡眠检测 + 失败退回直连，
但界面对此的表达是**零**。这是本次重构的第一优先级，不是「好看」问题，是**功能已经做了但用户看不见**。

## 3. 信息架构裁决

### 3.1 结论速览

| 页面 | 承载什么 | 裁决 | 理由（依据） |
|---|---|---|---|
| 仪表盘 | 唯一的「现在怎么样」 | **保留 + 扩充**（P0） | 首屏 636 px 完全放得下；缺的只是 J1/J2 的状态 |
| 节点 | 节点库 + 延迟 + 切换 | **保留，不重构**（P3） | 单节点下搜索/二维码/删除都用不上，但**成本为零**且加节点时必需；重构收益 < 回归风险 |
| 订阅 | 凭据来源 + 用量 | **保留**（不动） | URL 是唯一凭据来源，用量条是服务器唯一给的真实字段（`05 §3.3`） |
| 规则 | 预设选择 + 自定义规则（声明） | **升级为「规则与判定」**（P1） | 它现在是**声明**，但用户问的是**判定**：「这个网站会走哪条」 |
| 拓扑 | 流图 + 判定 + 连接列表 + 规则链（4 件事） | **拆到 2 件事**（P0/P1） | 2.97 屏；真实数据被推到首屏外 |
| 地球仪 | 本机↔选中节点的一条航线 | **降级为拓扑的第二视图**（P2，保留一键可达） | 一级导航项只画**一条**航线，且首屏看不到它的事实面板 |
| 日志 | 原始日志 + 诊断报告 | **保留**（不动） | 它是唯一「未经我们加工」的真相源，也是自愈过程的唯一记录处；合并它会让原始证据被结构化视图吞掉 |
| 设置 | 唯一写入口（9 张卡） | **修锚点 + 把 3 个恢复相关项提到仪表盘**（P1） | 3137 px / 4.93 屏，恢复策略在 93% 深度 |

**明确不建议删任何一页。** 理由：8 页里每一页都有一个**不可替代的真相源** ——
日志是原始日志、设置是唯一写入口、订阅是凭据、节点是选择、规则是判定、拓扑是观测、
地球仪是地理投影、仪表盘是结论。「简洁」在这里不该靠删页实现，应该靠**减少每页要回答的
问题数**（拓扑 4 → 2）和**让首屏回答最重要的问题**。

### 3.2 四个结构性问题（按严重度）

**P-IA-1 · 仪表盘答不出「它在自己修吗」**（最严重）
`CoreRuntime` 只有 `running / pid / started_at_unix / config_path / tun_session /
tun_interface / routes_committed / last_error`（`types.ts:177-186`）。
自愈的四个事实全都不在里面，而且**项目自己的契约测试把它们登记为「界面不显示」**：
`apps/desktop/tests/type_contract.rs:169` ——
`("was_connected", "重连意图，由 Rust 侧读写，界面不显示")`、
`("auto_reconnect", "重连策略开关，界面目前没有对应控件")`。
这个决定在「仪表盘=状态」的模型下是自洽的，但在用户提出 J1/J2 之后**已经过期**：
用户要的不是「意图字段」，是「现在到底在不在修」。
另有三个副作用：
* 重连期间 `runtime.running=false` → 状态词是「未连接」，主按钮是「连接」——
  **恰好就是他抱怨的那个操作**；
* 看门狗重建会让 `supervisor.rs:347` 重写 `started_at_unix` → 「已运行 12 分钟」
  **无声归零**，用户会读成「它刚断过又连上」；
* 重建成功后 `last_notice` 没被清（`core.rs:508-513` 只写日志），
  而「网络中断，正在自动恢复…」这条提示是 `collectNotices` 里 **rank 4/5**
  （`Dashboard.tsx:327-340`），只要有更高优先级的提示在，它就**根本不显示**
  （`visible = primary ? [primary] : []`，`:71`）。

**P-IA-2 · 拓扑页 2.97 屏里，2/3 是装饰，真实数据在首屏外**
631 px 的车流图占了首屏 99%。这不是说图没价值 —— 用户明确要过「车沿着线走、看到一整个流程」——
而是**信息层级放反了**：一屏只有 636 px，图应该当背景/结构，把
「最近连接」（真实 `[入站→出站]`，来自访问日志）和「某个地址会走哪条路」（真实判定，
已与核心对拍）放到它前面。按 `CONNECTIONS.md` §2 的口径，**这两块才是「不编」的部分**，
流图是「结构上可能」（`docs/ui/topology/README.md` §「一处刻意的口径」）。

**P-IA-3 · 「规则」这件事有两个来源、三个去处**
* 声明：`Routing.tsx` 的预设 + `settings.custom_rules`（**只显示用户自定义规则**）；
* 判定：`Topology.tsx:1461` 的 `DestChecker`（输入域名 → 命中哪条规则 → 哪个出站）；
* 生效顺序：`Topology.tsx:290-308` 的「规则链（8 条）」。
用户在「规则」页看不到**生效规则链**，在「拓扑」页用判定器；两页相距一次导航 + 1.2 屏滚动。
按「声明 vs 观测」分线：**声明侧（预设 + 生效链 + 单点判定 + 自定义）全部归「规则」页，
观测侧（流图 + 最近连接）归「拓扑」页。**

**P-IA-4 · 设置页 9 张卡只有 4 个锚点，且 id 重复**
见 §2。这是 0.8.1「分组 + 锚点导航」那一轮留下的实现缺口：`Fake-IP`、`DNS 解析器`、
`TUN 模式`、`核心与数据更新`、`特权助手` 五张卡没有可达锚点。
另有 3 个直接影响 J1/J2 的开关集中在 `其他` 卡（`开机自启动` 2913 px、
`在标题栏显示实时网速` 2942 px、`退出时还原系统代理` 3015 px）。

### 3.3 目标信息架构

导航从「8 个平铺项」改成「**3 组**」，页数不变（地球仪并入拓扑后 7 项）：

```
现在（结论）        想知道（观测/判定）        管理（数据）        排障
─────────────      ─────────────────────      ─────────────      ────────────
仪表盘              拓扑（流向视图）             节点               日志
                    ├ 地球仪（地理视图）         订阅               设置
                    规则（声明+生效链+判定）
```

* **仪表盘**：状态 + **恢复过程** + 流量 + 最急的一条提示。
* **拓扑**：默认「流向」视图 = **最近连接（首屏）** + 流图（结构示意）+ 口径说明。
* **规则**：预设 + **生效规则链** + `DestChecker` + 自定义规则 + 折叠的落盘位置。
* **地球仪**：拓扑页的第二个视图（地理），入口在页头，一键可达、URL 可寻址。
* 节点/订阅/日志/设置：**本轮不动结构**。

## 4. 优先级（做什么，以及**不做什么**）

### P0 —— 不做会持续伤害用户信任

**P0-1 · 让「自愈」可见（后端快照 + 仪表盘 + 预览场景）**
用户最反复的需求，后端已实现，成本主要在**把已有的事说出来**。
禁止前端自行推断重连次数 —— 所有计数必须来自后端。

需要暴露的最小字段（字段名留给实现定，语义不能含糊）：
* 重连/重建**进行中**（布尔）· 第几次 / 共几次 · 上一次失败原因 · 触发原因
  （开机重连 / 换网 / 唤醒 / 节点抖动，后端已经知道：`slept_for`、`network_moved`；
  **不要**让前端猜）；
* 看门狗最近一次探测的**时间戳与结果**（当前 10 s 一轮，全部只写进 `logger`/`tracing`）；
* 会话内**核心重启次数**：后端已经有 `MonotonicCounters.resets()`（`stats.rs:388`、
  `max_resets()` `:420`），目前只通过 `Topology.counter_resets` 在拓扑页露过一次
  —— 把它提到仪表盘，重连就不再是「无声的」。
* `was_connected` / `auto_reconnect` 的**显示口径**（不是原样回显意图，而是
  「除非我主动断开，否则不该断」这句话的当前真值）。

**P0-2 · 拓扑页首屏重排（真实数据优先）**
把「最近连接」提到流图**之前**；流图高度压到首屏能露出连接列表第一行；
`traffic_ok=false` 的说明从图**下方**移到**上方**（现在 `Topology.tsx:265-271` 在
`MemoHighway` 之后）。**保留**图，不删 —— 用户要的是「看懂流程」，做法是降层级、不是砍掉。

**P0-3 · 地球仪三处修正（一次做完）**
① 文案：`Globe.tsx:108`「飞机的数量与快慢由**实测速率**决定」→ 改为累计流量
（代码 `vehicleCount(route.bytes)` `:630`，与拓扑页 v0.8.25 已改的口径对齐）；
② 主指标：`RouteFacts`（`:142-155`）把**字节**放到 `facts__km`（15 px/强调），
距离降到 `--small` —— 全应用只有这里把「大圆距离」当主数字，而距离是最不可行动的字段；
③ 首屏：事实面板 top **672**、操作提示 top **641**，都在 636 之外 → 画布必须让出高度，
让「起点/出口/流量/操作提示」落进首屏。

### P1 —— 结构修复，一次一小步

**P1-1 · 「规则」页成为判定唯一入口**（搬 `DestChecker` + 生效规则链进规则页；
拓扑页删除这两块）。**保留**一个从拓扑到规则的链接（用户是在看图时产生「这个网站走哪」的疑问）。
拓扑页段落由此从 4 段降到 2 段。

**P1-2 · 设置页锚点去重**：9 张卡 → 9 个**唯一** id + 9 个锚点；顺手修
`Fake-IP` / `DNS 解析器` 不可达。恢复相关的 3 个开关在仪表盘恢复块里给
「调整」直达（不加新页面）。

**P1-3 · 空态/错误态补齐**（对应审查 E5/E6）：取拓扑失败必须是
`banner--error` + 「每 2 秒自动重试」+ 重试按钮（现在 `Topology.tsx:238-248` 是中性灰 `.note`，
与 `Globe.tsx` 的红底不一致）；空拓扑必须给文案并隐藏图例。
**预览必须有 `?state=traffic-error` 与 `?state=empty-topology` 两个场景**
（现在只有 `?traffic=unavailable`，`preview*` 拆分后仍在）。

### P2 —— 视觉与密度（定**顺序**和**绑定关系**，具体做法归 art/interaction）

**当前状态已核实**：`segs` 仍然 `push(p.fwd, p.back)`（`Topology.tsx:1082`），
回程腿以 `.flow__route--trunk` 渲染（`:1330`）；`styles.css:1700` 仍是 `opacity: .3`；
车仍是 `rect 9×5`（`:1355`，无 `rotate`）；图例色块仍是 9×5 实心块（`styles.css:1672`）；

**P2-2 · 密度交互**：hover 隔离（`.flow` 的 `pointer-events: none` 需在子路径上覆盖）；
「按入口展开」另开一轮，不与动画修复混做。

**P2-3 · 「同一屏两个断开按钮」**：交给 interaction-designer 出一个结论
（保留哪个、另一个如何降级），本 PRD 只登记这个问题与证据。

## 5. 核心场景与卡点

### S1 开机后确认「它自己连上了」（频率：每天 1 次以上）
1. 开机 → 应用自启（`SMAppService`，`docs/02 §6.5`）→ 后台开始重连（最多 2 分钟）。
2. 他打开窗口。
3. **卡点**：仪表盘写「未连接 · 核心没有在运行」，主按钮是**「连接」**
   （`Dashboard.tsx:61-67`、`:112-120`）→ 他点下去，而应用其实**已经在重试**
   （重连启动只写 `info` 日志，默认日志级别是 `warning`，`model.rs:788-790`，
   连日志页首屏都看不到这句话）。
4. 期望：首屏直接说「正在自动重连（第 N/24 次）」或「已自动重连（第 3 次成功）」，
   并且**不出现一个看起来必须点的「连接」**。

### S2 换网 / 合盖唤醒后确认是否恢复
1. 咖啡厅 → 家，或合盖 30 分钟再打开。
2. 看门狗 10 s 一轮探测，连续 2 次失败才重建（唤醒后 1 次）→ **10–30 s 的窗口**。
3. **卡点**：这 10–30 s 里界面仍然显示「已连接」且**没有任何在确认的迹象**；
   重建成功后 `started_at_unix` 被重写，「已运行」分钟数**无声归零**，
   而事后唯一的证据是拓扑页底部那句「核心重启过 N 次，累计流量已续接」。
4. 期望：能回答「刚才断过吗、什么时候、现在好了没」。

### S3 这个网站走了哪条规则
1. 打开某网站很慢 / 打不开。
2. 想知道它命中哪条规则、从哪个出口出去。
3. **卡点**：判定器在**拓扑**页（top 760，需滚 1.2 屏），而「规则」页只有四个预设的文字说明
   和「自定义规则」——**看不到生效规则链**。他要么滚拓扑页，要么去日志页翻。
4. 期望：在「规则」页输入域名 → 直接得到「命中 X 规则 → 出站 Y」，与生效链在同一个视口。

### S4 这条连接实际去了哪个出口（要看得懂）
1. 用户要「看到一整个流程」。
2. 流图告诉他的其实是**结构上可能**（配置里的 3×6 扇出），不是实际发生；
   实际发生的那份在「最近连接」里（top 931，第一行 1193）。
3. **卡点**：他会在流图上找「我这条连接在哪」，而流图**不表达逐条归属**
   （上游没有 per-rule 计数器，`topology/README.md` §口径）。
4. 期望：首屏就能看到真实连接列表；点一条 → 图上高亮它那条路（v0.8.26 已实现）
   并**明确写清**「高亮的是这条连接的入站→出站，不是它的字节」。

### S5 判断「我看到的图是不是真的」
1. 他看到车在跑，但流量卡是 `0 B` / 查不到。
2. **卡点**：`traffic_ok=false` 的说明在图**下方**（`Topology.tsx:265-271`），
   卡片虽然已改显示「流量不可用」（v0.8.25 的成果），但**图的解释权在图之后**。
3. 期望：任何会影响判读的口径说明（流量不可用 / 内部通道的字节是盲区 /
   累计值跨重启已续接 / 域名是时序配对）都在**它解释的那个东西之前**。

## 9. 我拿不到的 / 待确认

1. **真实用量**：没有遥测，§1/§3 的「他用哪些页」是**推断**（需求 + 迭代史 + 代码事实）。
   若用户能提供一句「我平时只开仪表盘」，本文的排序会更硬。
2. **真机 UI 行为**：所有数字来自 `?preview=1`（mock）。**真机上是否一致，本文不声称**。
   macOS WKWebView 无 CDP；WebKit Remote Inspector 需手工操作、不可自动化。
   本 PRD 的验收判据因此**只用于预览页与单元测试**，真机需要人来点一遍（尤其 P0-1/P0-2）。
3. **重连期间的精确时长**：24×5s 与 10s 看门狗、2 次失败阈值是**读代码**得到的
   （`core.rs:954-956`、`:886`、`:402-500`），没有真机计时样本。
4. **`?state=empty-topology` 与 `state=reconnecting` 两个预览场景目前不存在**，
   P0/P1 的判据依赖它们先被加上（属于前端实现，不在我的写入范围）。
5. **未验证**：`counter_resets` 在会话内的语义边界（它统计的是采样器观察到的归零次数，
   不是「用户可感知的断线次数」—— 一次重建是否必然产生一次归零，我没有实测）。
   实现 P0-1 时必须由后端给出明确定义，**不许前端把「重启次数」当「断线次数」卖**。
