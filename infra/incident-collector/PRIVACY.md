# 隐私说明：现场包上传（面向用户，可直接引用）

本页说明「一键现场包」上传后会**存什么、不存什么、存多久、怎么删**。
它的每一条都与代码一一对应：端点源码 `infra/incident-collector/src/worker.mjs`。

## 一句话

**只存你点「上传」时给的那个 zip，以及一份不含日志正文的清单（manifest）；不存你的 IP、账号或订阅信息；30 天后自动删除；你可以要求删除。**

## 1. 存什么

| 项 | 内容 | 为什么需要 |
|---|---|---|
| 现场包 zip | 本机脱敏打包出来的那个文件（上传前你能看到包内清单，见 App 里的 `README.txt`） | 这是排查问题的材料 |
| `manifest.json` | `id`、`sha256`、字节数、content-type、接收时间、保留天数 | 让你能核对「传的和我拿到的是同一个文件」；也用于定位与到期 |

`id` 形如 `INC-20260922-120000-3f2a`：**UTC 时间 + 2 字节随机数**，**不含任何用户标识**（不是你的设备/账号）。

## 2. 不存什么（刻意不采集）

| 不存 | 说明 |
|---|---|
| **客户端 IP** | 我们**不把 IP 写进 R2**。上传是公开端点、需要防滥用，所以做「按 IP 的限流」，但键是 **`SHA-256(每次启动随机的 salt + IP)` 的前 16 个 hex**，**只在内存里**，重启即消失，也不进持久层。 |
| User-Agent / 设备指纹 | 不记录。 |
| 账号 / 订阅 URL / 节点 UUID | 不记录（这些也不该出现在包里：打包脚本会先做脱敏，且**打包前会展示清单让你自己看**）。 |
| 日志正文进 manifest | manifest 只有元数据；原始 zip 只有持有端点令牌的维护者能取。 |
| 请求日志 | Worker 未开启 observability（`wrangler.toml` 里 `[observability] enabled = false`）。 |

**唯一可选的「自述」字段**：如果客户端显式发送 `X-XrayTun-Client`（例如 `XrayTun/0.8.35`）
且格式合法（≤64 字符的 `[A-Za-z0-9._/+-]`），manifest 里会记下它 ——
它只是**版本号**，用来判断「这是哪个版本的问题」。不发送就没有这个字段。

## 3. 存多久

**30 天**，两道保证：

1. **R2 lifecycle 规则**（`expire after 30 days`）——存储层自动删除；
2. **端点内的惰性过期**（**只对「被读到」的对象生效**）：读取超过 30 天的 id 会被当作不存在，
   并顺手把 zip 与 manifest 一起删掉；**没人读过的对象由第 1 条负责**。

> 为什么要写这句「只对被读到的生效」：第 1 条（lifecycle 规则）曾经**事实上不存在**过一段时间
> （旧文档里的命令必然失败、又被 `|| true` 抹平，见 `README.md` 与
> `docs/verification/INCIDENT-ENDPOINT.md` §14）。若只写「两道保证」而不写各自的作用范围，
> 容易把「有惰性过期」误当成「反正会删」。写清边界，下一次同样的失配才能立刻可见。

## 4. 谁能读

| 内容 | 谁能读 |
|---|---|
| manifest | **任何人知道 id 就能读**（它只有元数据，不含日志内容、不含 IP） |
| 原始 zip | **只有持有 `INCIDENT_TOKEN` 的人**（维护者）。请求必须带 `X-Auth-Token`，且服务端用常量时间比较 |
| R2 桶 | Cloudflare 账号持有者（= 用户本人） |

## 5. 怎么删

1. **随时**：`DELETE /api/incident/<id>`（带 `X-Auth-Token`）会同时删掉 zip 与 manifest ——
   用于「用户要求删除」；
2. **到期自动**：30 天后 lifecycle 删除（见上）；
3. **彻底停止**：维护者 `npx wrangler delete`（摘掉端点）+ `npx wrangler r2 bucket delete xraytun-incidents`
   （清空数据），用户再吊销 Cloudflare API Token。步骤见 README「回滚 / 撤销」。
   （桶名带 **s**：真实名是 `xraytun-incidents`，见 `wrangler.toml` 的 `bucket_name`。
   写错一个字母这条命令只会返回 `bucket not found` —— 而这一步正是「用户要求彻底删除数据」，
   最不该失效的一步。）

## 6. 上传是「你点的那一下」

**没有静默上传**：只有你在 App 里明确点击才会发送；
打包**之前**会生成一份 `README.txt` 列出包内文件，**你可以先看再决定**。

## 7. 已知边界（如实说）

* 限流是 best-effort（每个 Cloudflare isolate 一份内存），**不构成安全边界**；
* manifest 是公开的：知道 id 的人能看到「某个时间收到了一个多大的包」，仅此而已；
* 数据存放在 Cloudflare R2（你账号下的桶），受 Cloudflare 的服务条款约束；
* 端点**不会**替你判断包内是否含敏感信息 —— 那由打包脚本的脱敏 + 你自己的检查负责。
