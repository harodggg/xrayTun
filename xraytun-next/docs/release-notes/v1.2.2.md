# xraytun-next v1.2.2 —— 修掉一个「界面在说假话」的切换 bug，并把「第一次双击」的指引放进 DMG

> 这一版来自一次**独立体验官走查**（fresh-context agent，按「刚下载完 App 的普通 Mac 用户」
> 代入，只读源码与发布说明）。它找出的第一位卡死点是 Gatekeeper，**最危险的一处是静默降级**：
> 连着 TUN 时在节点页切节点，实际掉回本机 SOCKS，而界面继续显示「TUN 模式 · 已连接」。

## 一、先看这里：第一次双击打不开（未公证）

这个 App **没有 Apple 开发者签名（未公证）**，所以下载后第一次双击，macOS 会弹
「无法打开，因为 Apple 无法检查其是否包含恶意软件」。那是系统对「没公证」的默认拦截。

三种打开方式（任选其一）：

1. **最快**：在「应用程序」里按住 **Control** 点（或右键）XrayTun.app → 选「打开」→
   对话框里再点一次「打开」；之后双击就正常了。
2. **系统设置**：先双击一次（被拦）→「系统设置 → 隐私与安全性」→ 找到 XrayTun 那条 →
   点「仍要打开」→ 再双击。
3. **终端**：`xattr -dr com.apple.quarantine /Applications/XrayTun.app`

同一份说明这次也**放进了 DMG 里**（`首次打开请看这里.txt`）—— 卡住的那一刻它就在你眼前。

## 二、修好的（按危害排序）

1. **TUN 会话下切节点不再静默降级成 SOCKS**（`crates/xt-daemon/src/flow.rs`）。
   旧行为：`Switch` 一律走代理流程（生成 SOCKS 配置、`tun_fd: None`），而状态机沿用旧的
   `mode: Tun`，等的是**永远等不到**的 `RoutesCommitted` —— 界面于是显示「TUN 模式 · 已连接」
   （或卡在「提交路由中」），用户的全机流量却已经没有被接管，旧 utun/默认路由还可能挂着。
   现在：切节点落在 TUN 会话上时，先走**与「停止」完全相同的路径**（停核心 + `helper.tun_down`
   回滚路由与 DNS），再按 TUN 连新节点 —— 正是状态机文档里写的「切换 = 停掉旧的，按新节点
   重新走一遍」。切换期间界面会如实显示 断开 → 连接 → 已连接。回归判据是一条纯函数单测
   （`switch_needs_tun_flow`）。
2. **第一次双击的指引**进了 DMG（见上）+ 发布说明（本页）。
3. **连不上 daemon 时，界面告诉你为什么**：壳在启动 daemon 那一步的结论（没找到二进制 /
   spawn 被拒 / 报就绪前就退出）以前只进 `eprintln`；现在通过 `daemon_launch_report` 命令交给
   界面，连不上时在错误下方显示那句话**和 daemon 日志路径**。壳没给结论就什么都不显示 ——
   界面不替壳编「启动失败」。
4. **失败时知道一手现场在哪**：仪表板上的失败现在同时给出 daemon 日志路径（来自壳），
   不再只有一颗「查看日志」按钮。
5. **订阅拉不动的报错更像是人话**：HTTP 4xx/5xx 现在由 curl 的 `--fail` 归因（不再把错误页
   送去解析、报成「不是合法订阅」）；解析不了主机名 / 连不上 / 超时（curl 6/7/28）会额外附一句
   **标注为推断**的提示（先确认网络、再确认订阅地址），并带上脱敏后的 `scheme://host/…`。
6. **卸载特权助手到底删什么，界面说的和脚本一致**：逐字列出 launchd 配置、助手二进制、
   `/var/run/xraytun-helper.sock`，并说清留下的是状态目录 `/Library/Application Support/XrayTun`
   （路由/DNS 快照，用来在被改乱后还原网络）。以前只写了两样、也没提留下的东西。
7. 顺手加固：daemon 的 AF_UNIX socket 绑定后权限收紧到 0600（这条连接会回传含订阅令牌的 URL）。

## 四、仍然没有做到的（不许含糊）

- **TUN 真机接管没有验收过**：helper 安装、授权弹窗、`utun`、路由与 DNS 提交，
  这几步 CI 跑不了（装不了 launchd 守护服务），只能在你自己的 Mac 上验。
  本版能说的是「通路已宣告 + 失败如实报错 + 切换不再撒谎」，**不是「能翻墙了」**。
- **未公证**（无 Apple Developer ID，S5 未做）：Gatekeeper 的行为以你真机为准；
  杀毒软件也可能拦被安装的助手。
- 订阅**没有定时自动刷新**（只有你点「刷新」）；「贴一条订阅 URL 就自动更新」仍不成立。
- 订阅正文的大小限制是两道（`--max-filesize` 5 MiB + 长度复查 + 20 秒超时）：
  源站用 chunked 不给长度时，curl 仍会把正文读进内存 —— 对「用户自己填的 URL」够用，
  但不构成「内存上限」的证明。
- 托盘菜单的「退出 XrayTun Next」只退**界面**，daemon（以及正在跑的隧道）会继续运行；
  想彻底停掉请先在仪表板按「停止」。

## 五、怎么验（给真人的最短路径）

1. 打开 App（卡在 Gatekeeper 就看第一节）。
2. **节点**页：粘订阅原文或分享链接 →「导入」；或**设置 → 订阅**填 URL →「添加订阅」。
3. 节点页点某一行的**「选为当前节点」**。
4. 仪表板按**「启动」** —— 第一次会要你装特权助手（一次管理员授权，必须给）。
5. 连上之后再点另一个节点的**「切换并立即使用」**：现在它会**先断开再按 TUN 连上新节点**
   （界面会走一遍 断开 → 连接），而不是悄悄掉成 SOCKS。
6. 收工：按「停止」；再到设置里**卸载特权助手**看一段卸载范围说明。
