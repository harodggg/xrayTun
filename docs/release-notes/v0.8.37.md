> ## 本版修一个**启动阻断**：自定义规则 id 与预设/内部规则同名时，核心会拒绝启动
>
> **症状**（用户原文）：核心起不来，报
> `Failed to start: main: failed to create server > app/router: duplicate ruleTag preset-private`。
> 触发条件很普通：你的自定义规则里存在与**当前预设**（或 App 的**内部规则**）**同名的 id** ——
> 生成配置时两边原样拼接，于是出现重复的 `ruleTag`。
>
> **修法（不碰你的规则）**：给重复的标识加**确定性后缀**——首次出现保持原样，之后是 `#2`、`#3`…
> （界面上可能看到 `preset-private#2`）。**不删除任何规则、不改条件与出站、不写你的 `settings.json`**。
> `ruleTag` 只用于 Xray 日志排障（`Hit route rule: [tag]`）、**不参与匹配** ⇒ 改名**不改变路由语义**。
> **升级后无需改任何设置即可启动。**
>
> **若你还没升级、且正好处在这个组合**：临时办法是切到不含同名 id 的预设，
> 或者删掉那些与预设同名的自定义规则。
>
> **本版不需要重装特权助手**（`v0.8.35..v0.8.37` helper 侧无生产行为变化、协议号未变；
> 若你还没为 v0.8.35 重装过，那一次仍建议补上 —— 详见下面「助手」一节）。
> 诊断文案也改了：现在先给**结论 + 指名冲突的 tag + 几次 + 来源 + 下一步**，再附**末尾 8 行**核心输出
> （失败时 stderr 常为空、stdout 是一屏机器话）。实测：修前 **3,468 字符 / 35 行**，
> **主因是 `log_level=debug`**（这版配置带 `loglevel=debug` ⇒ 含 10 行 `[Debug]`；
> 用 `warning` 级对照只有 4 行 / 382 B 量级）；修后 **522 字符 / 9 行**。

## 助手：**本版不需要重装**

本版**没有**任何助手侧**行为**改动（`crates/xt-proto` 未改 ⇒ 协议号不变 ⇒ 设置页不会报「版本不匹配」）。
helper 侧有一处**结构重构**（`uninstall` 主体抽成 `uninstall_with`，生产用真实闭包调用）：
求值顺序（左到右：内存那份会话 → `force_cleanup`）、文案、`warn` 时机、副作用顺序**逐项对照相同**。
新增的**注入入口**（`TestExecutor` / `with_test_root`）只在测试构建里存在。
**若你已为 v0.8.35 重装过助手，不必再装**；**若还没为 v0.8.35 装过，请重装一次**
（v0.8.35 的「回滚失败不再被静默」修复在助手侧）。

## 这一版还改了什么

* 核心**诊断文案**：起不来时先给结论与下一步，再附末尾 8 行日志，不再只丢一屏机器话；
* **守卫第二轮**（内部测试机制）：把「源码文本守卫」的判据从**字面形状**改成**只锚语义** ——
  以前「无害的形状变化」（例如把绑定改 `mut`、给变量起别名）会**假红**，
  而「站点自己造一个成功响应」「把留痕塞进不可达分支」这类真绕过又抓不住；
  现在两类都被钉住，并补了 `s3` / `m5` 反例与 `p1` 正向 fixture；
* 卸载站点的**站点级行为测试**：注入两路失败后直接断言最终响应文案
  （不驱动真实的 `launchctl` / 删系统文件 / 回滚真实快照）。

* **UI 防呆（看得见的提示）**：规则 id 与预设/内部规则重名时，**切预设之前**就能看到 ——
  两条判据强度不同：**硬证据**是运行中的配置里出现了 `#2`/`#3` 后缀（「**确实**撞了」），
  **条件句**是 id 用了 App 自有前缀 `preset-`/`internal-`（「**如果**目标预设里也存在同名规则…」）。
  **两条都要**：你当时的预设是「自定义」，运行中的配置里看不到 `#n` ⇒ 只有条件句能提示你。
  （**严格版「与目标预设同名」的判定还没有**，需要在快照里暴露每个预设的 id 集合 ⇒ 已排 v0.8.38；
  真机 WKWebView 未验证。）

## 诚实边界

* **真机「在 App 里切预设 → 启动」这条 UI 路径未验证**；验证到的是
  **「生成路径 + 真实核心 `xray run -test`」**：修后 10 份配置全部 `exit 0`，
  把唯一化去掉（回到修前）则复现用户**逐字**报错且核心 `exit 23`；
* 唯一化只在**生成配置时**发生，**不改你磁盘上的 `settings.json`**
  （实测该文件 sha256 未变）。
