信息过滤器 · Jev：用 Jev 的类型化决策过滤 X 时间线上的垃圾信息

这是一个 Chrome MV3 扩展。它在本地预筛，再用 Jev（TypeSafe System One）问几个类型化问题 （「属于哪一类垃圾信息」+ 色情 / 引流 / 欺骗三条独立证据 + 危害程度评分）， 拿到类别、概率与置信度之后才决定动作：命中即隐藏； 只有高置信度的类别才会动账号（静音/拉黑），而且默认只演练、不真的点。 它不是关键词黑名单 —— 判定在模型那一层，关键词只用来决定「值不值得花一次调用」。 除过滤外它还做两件整理的事：β（贝塔信息）把重复/类似/语义相同的内容 折叠成一条，α（阿尔法信息）把「与评论区多数观点明显不同」的特殊观点标出来（只标记、不隐藏）。

它和 XrayTun 是什么关系：同一个作者的两个独立项目

本页介绍的是 信息过滤器 · Jev，它与 XrayTun 是同一个作者的另一个独立项目：XrayTun 是 macOS 的 Xray 图形客户端， 本项目是一个浏览器扩展，两者不集成、不共享代码、不互相依赖， 也不能用本项目去配置或管理 Xray。放在同一个站点上，是因为它们出自同一作者， 而不是因为它们属于同一个产品。

六类垃圾信息，各自可开关

关掉某一类 = 该类别不隐藏、不动作（连兜底路径一起失效）。类别由模型判定， 本地预筛只决定「值不值得花一次调用」。能不能动账号是类别属性，不是阈值属性。

类别 典型形态 可动账号？
色情 / 性交易引流 同城约、福利姬、主页联系、擦边诱饵贴 可以（高置信度）
诈骗 / 博彩 / 荐股 稳赚不赔、内幕消息、杀猪盘、首充返水、加群下注 可以（欺骗证据达标）
广告 / 导流 / 带货 点主页、加微信、私信我、招商代理、扫码领券 可以（强引流 + 高程度）
标题党 / 情绪煽动 不看后悔、删前速看、99% 的人不知道、fake urgency 不可以，只隐藏
低质 AI / 洗稿 / 无信息量 车轱辘话、拼接稿、关键词堆砌、AI 模板腔 不可以，只隐藏
刷屏 / 重复文案 / 机器人农场 同一段文案被多个账号在短时间内复制（结构信号，不走模型） 不可以，只隐藏

它怎么判定：四层，逐层加钱

判定不是一次模型调用决定的，而是分层做：便宜的先做，贵的只在必要时做； 任何一层单独出现都不足以触发账号级动作。

层 做什么 成本
本地预筛 可读正则扫正文、显示名、卡片文案与图片 alt；对「emoji 拆字」 （处🐕男）会先去符号再匹配；白名单、自己发的、超短无媒体直接跳过 0 请求
预检（模型先行） 没被关键词命中的推文也会被问一句廉价单问（「这是不是垃圾/诈骗诱饵/低质填充」）。 ≥0.75 再问完整五问；≥0.65 只隐藏成待确认 一次单问（约五问的 1/5）
重复文案农场 同一段无实质内容的话被 ≥2 个不同账号在 30 分钟内复制 → 全部隐藏 （含更早出现、当时被判放行的那几条）。**近似去重**（3-gram 重叠系数 ≥0.8）：同一句各插不同垃圾字符、重复写两遍都算同一段；归一会吃掉 emoji、标点与大小写 0 请求
Jev 类型化五问 属于哪一类？是否色情？是否站外引流？是否欺骗/诱导？危害程度几级？—— 问题用英文写给模型，原文不翻译 一次调用

三条不变量（写进代码注释、也有单测守着）：① 账号动作需要「可动账号的类别 + 类别置信度达标 + 危害程度达标 + 至少一条硬度证据 （色情/欺骗/强引流）」；预筛、图片肤色、文案农场、视觉模型、预检信号 单独出现最多到「隐藏」或「待确认」，永不拉黑； ② 模型不确定时降级，不做二次猜测；③ 每一档都写明原因（过滤条与审计日志里能看到类别、概率与原因）。

命中之后做什么，完全由你决定：默认是演练模式—— 只把「本应静音谁」记进审计日志，不点任何菜单。想让它真的动作，需要你在弹窗里显式打开 「自动静音」甚至「连『隐藏』档也静音」；拉黑这一档永远只认高置信度的动作档。

除过滤之外：β 折叠重复、α 标出特殊（v0.4.0 新增）

过滤是「把噪音拿掉」，这两件事是「把信息理清」—— 它们纯展示， 任何情况下都不改变隐藏判定与账号动作（不变量 I① 不变），可以各自关掉。

概念它做什么边界
β · 贝塔信息 重复 / 类似 / 语义相同的信息 → 折叠，时间线里只显示一次。 不是字符串相等：先按本地近似度（3-gram，同线程/同农场簇也算候选）挑最多 6 条， 再一次 Jev 批量调用问「是否表达同一信息/同一主张」（翻译、改写、转述都算同一）， 命中的那条折叠成细条：与 @… 的内容相同 · 还有 N 条相似内容 · [展开]，点「展开」可还原。 代表条不折叠；只折叠「同一件事」，同线程的不同观点不算
α · 阿尔法信息 回复区里，若一条回复的观点与多数评论明显不同、且是有实质内容的观点， 加一枚 α · 与评论区多数观点不同 徽标。 只标记，不隐藏、不折叠；默认只在回复区判定

成本可以自己量：本地没有候选就不调用；每次推文最多 1 次语义调用， 实测单次约 536 输入 token（34 条真实样本里 11 次语义调用、共 5898 输入 / 330 输出）。 设置页 1.6 节可调阈值、候选数与参考评论条数，弹窗有「折叠重复信息（β）」「标记特殊观点（α）」两个开关； 超预算或调用失败只跳过整理并计数，过滤结果照常返回。

v0.4.2：情绪 / 认同 / 确认类附和只留一条

认同 / 确定 / 哈哈哈 / 纯 emoji 这类没有实质内容的附和，现在同一线程只留最早一条， 其余折叠成一条细条：与 @… 的同类附和（情绪/认同/确认） · 还有 N 条同类回复 · [展开]。

它们是字符串不同、语义同类的东西，所以走新的本地分类（β.kind = agreement）， 0 次模型调用：不花额度，也不影响隐藏与账号动作。判定保守 —— 不同意 / 不确定 / 确实有问题 / 同意，但前提是数据要公开 / 疑问句 / 带数字或链接的回复一律不折叠；只在回复区、同一线程内生效。 这类回复通常只有 2–4 个字（本来会被「过短无媒体」本地跳过），现在跳过的是判定，展示层的折叠照旧。 设置页 1.6 节可关。

同时把 只入身体…不入生活 收进强特征：加规则前本地零信号，单条只能拿到预检 0.69 → 仅「待确认」； 现在单条即走完整五问（实测乱码账号名那条 → hide，带「找炮友」显示名的 → block）。 新闻/讨论语境下自动降级成 1 分，引用这句话不会被隐藏。

v0.4.3：第三个引流黑话模板，命中即隐藏成待确认

用户第三批截图里有一条：Jonathan Fisher · 玩归玩闹归闹🌹🍷给你看福👍我不开玩笑 X 6。 它文案里没有露骨词，模型给 adult 0.03 / ordinary；本地也没有信号 （「玩归玩闹归闹」本身是大众梗，单独出现不能定罪）→ 旧版整条放行。这一版：

  • 新规则 zh_meme_fuli：玩归玩闹归闹 … 给你看福 / 看福利 —— 两段必须同时出现才命中，单独一句「玩归玩闹归闹，别拿安全开玩笑」绝不触发。
  • 新增规则的「review 下限」（reviewFloor）：这类黑话模板命中后， 即使模型说 ordinary 也隐藏成待确认（原因 solicit_template）—— 和「显示名即引流」「X 标垃圾分区」同一档：只隐藏、绝不动账号； 模型给出 hide/block 时仍以模型为准。新闻/讨论语境降级成 1 分时，这个下限同时失效， 引用这句话不会被隐藏。

同批账号的另外两条本来就能抓：处男无偿 + 只入身体🌻😊不入生活 → hide（adult 0.89）； 👆只入身体❤️👄不入生活。4 → hide（归一化后与同批同文案，农场命中）。

v0.4.4：情绪言论折叠/隐藏，并标出是哪一类情绪

「把所有的情绪言论给折叠/删除，然后给予愤怒，喜悦，支持，反对，之类的信息」—— 现在： 愤怒 / 喜悦 / 支持 / 反对 / 悲伤 / 确认 / 表情（纯 emoji） 七类情绪由本地分类器识别， 0 次模型调用，不占额度、不影响隐藏与账号动作。

模式（设置页 1.6 节）行为
折叠（默认）同线程同类情绪第一条保留并挂「情绪 · 愤怒」徽标（让你知道这是哪一类），其余折叠成 情绪 · 愤怒：与 @… 的同类情绪回复相同 · 还有 N 条 · [展开]
隐藏（= 删除）全部折叠，一条都不显示；条上写明这是哪一类情绪，点「展开」仍可看

判定保守：只有「整串恰好是一句情绪短语（可带加强语和语气词）」才算情绪言论 —— 我不同意，公开数据其实是反过来的（讲理由）、疑问句、带数字或链接、超长文本 一律不折叠：折叠的是情绪，不是论点。不同类别各自归组（2 条愤怒 + 2 条喜悦 → 两条代表 + 两条折叠）， 只在回复区、同一线程内生效；纯展示，随时可「展开」。

v0.4.1：用户发来的三条真站样本，两个漏检都补上了

X 回复区里会有一段被折叠的「可能的垃圾信息」，点开才看得见。用户把里面的三条发来后， 真模型实测：两条被判 block / hide，第三条**连模型都没问**（正文只有三个字、无媒体 → 本地跳过）。这一版补上两处：

样本现在的判定靠什么
已老实（X 标垃圾分区内，正文 3 字）review（隐藏成待确认，不动账号）X 自己的分区标题被当作结构信号 x_spam_section
只入身体🥦🌰不入生活（显示名「找炮友」）block（演练下 would=mute）预检 + 五问（成人 0.94）
只入身体🦵💪不入生活（同句变体）hide文案农场：归一化后只有 8 个有效字符，阈值从 10 降到 8 才聚得起来

两条原则没有变：X 的分区标记只是结构信号，永远只到「隐藏成待确认」，绝不据此动账号； 8 字阈值也不会误伤 —— 2 个账号的农场命中还要过内容信号闸门（成人/欺骗/引流/本地特征/预检诱饵）， 「两个人恰好发同一句 6–7 字寒暄」不会被隐藏。普通时间线里的 3 字推文仍然本地跳过，省下调用。

安装与配置

扩展不需要构建，下载 zip 解压就是一个可直接加载的目录：

# 1) 下载并解压
unzip jev-x-filter-0.3.0.zip -d info-filter

# 2) 打开 chrome://extensions → 右上角打开「开发者模式」
#    → 「加载已解压的扩展程序」→ 选中解压出来的 info-filter 目录

# 3) 点扩展图标 → 打开设置 → 第 1 节「Jev 接入」
#    · 想用自己的 Key：预设保持 TypeSafe 官方，粘贴 API Key
#    · 想零成本试水：预设切到 OpenCode Zen（jev-1.13-free，免密钥）
#    · 点「测试连接」，确认能拿回类型化答案

# 4) 在第 1.5 节勾选你要过滤的类别，刷 x.com
#    看过滤条与设置页的「审计日志」，确认没有误伤再关掉演练模式

判定发生在扩展的 Service Worker 里，API Key 只存在 chrome.storage.local， 不会下发到页面上下文。设置页可以随时导出/导入账号黑名单（JSON）， 也可以把误判账号一键加入白名单；弹窗里有六类快捷开关。

已知边界（用它之前该知道的）

  • 会误杀。判定是概率性的：性教育、艺术、健身、方言黑话、正当广告、 严肃新闻的标题都可能被拦或被放过。所有命中都能一键「显示」或「误判（加入白名单）」， 请把默认的演练模式当成观察期。
  • 自动静音/拉黑是真实的账号操作（通过点击界面菜单完成，不调用私有 API）， 存在平台风控风险。扩展做了限速、幂等与默认演练，但不能保证不被风控。
  • Jev 看不了图。纯图片内容只能靠本地肤色启发式 + 「只发图形态」隐藏成待确认； 它不会因为一张图就自动静音账号。需要更准的图片判定可以另配视觉模型端点。
  • 依赖 X 的 DOM。X 改版可能让菜单自动化失效；此时动作会记 action_failed 到审计日志，不会静默乱点：失败提示里会写明「菜单里实际有哪些项」 （鼠标悬停可见），拿它就能定位选择器漂移。选择器集中在一个文件里，便于跟随更新。
  • 需要你自己的模型额度。候选推文与预检各花一次调用，扩展内有限速与每日预算， 超了会降级成「待确认」而不是乱拦。
  • 它只服务于你自己的时间线卫生：不提供批量举报、不针对他人账号发起攻击， 也没有任何「把某人挂出来」的能力。

常见问题

β（贝塔信息）和 α（阿尔法信息）分别是什么？

β 把重复 / 类似 / 语义相同的信息折叠，时间线里只显示一次 （同一件事的翻译、改写、复述都算同一，判定在模型那一层，不是字符串相等），细条上可直接「展开」。 α 把回复区里与多数评论观点明显不同的特殊观点标出来 —— 只标记，不隐藏，免得你错过少数派信息。两者都是纯展示：不改变隐藏与账号动作，可以各自关掉。

自动静音/拉黑有时会失败吗？失败了会怎样？

会 —— X 改版、菜单文案换语言、或者你手动开着别的推文的菜单，都可能让自动化找不到目标项。 遇到这种情况它放弃并留痕：判定条上写「自动动作失败：… · 可点『立即静音』重试」， 鼠标悬停能看到「菜单里实际有哪些项」，同一条诊断也会进审计日志。它不会去猜一个 语义不明的菜单项 —— 误点「取消静音」或者点到别人的账号，比失败更糟。 v0.4.0 修掉了最常见的那类失败（隐藏推文后 ⋯ 按钮没有盒子 → 菜单不渲染）。

它能过滤哪几类信息？

六类，各自可以单独开关：色情与性交易引流、诈骗/博彩/荐股、广告导流带货、标题党/情绪煽动、 低质 AI 与洗稿、以及重复文案刷屏（农场）。前三类在高置信度时才可能静音/拉黑账号， 后三类永远只隐藏。

它会误杀正常内容吗？

会。判定本质是概率问题，任何过滤器都不可能零误伤，所以设计上把「误伤成本」压到最低：被拦的推文 随时可以点「显示」还原，点「误判（加入白名单）」会让该账号以后直接跳过，账号级动作默认只记录不执行。

自动静音或拉黑会不会导致我的 X 账号被封？

自动动作是通过点击界面菜单完成的真实账号操作，和手动点是一样的效果，因此存在平台风控风险。 扩展默认在演练模式下只记录、限制动作频率并保证同一账号只动作一次；建议先观察几天审计日志再关闭演练。

用这个需要花钱吗？

默认接入 TypeSafe 官方网关，需要你自己的 Jev API Key；也可以把预设切到 OpenCode Zen 的免费档 （模型 jev-1.13-free，免密钥）先零成本试水。扩展内有限速与每日预算上限， 超出后会降级为「待确认」而不是继续调用。

支持哪些浏览器？

支持 Chrome 120 及以上的 Manifest V3 环境，Edge、Brave 等同内核浏览器同样可以加载。 不支持 Firefox 与 Safari，因为它们的内容脚本与扩展 API 与 MV3 不同。

为什么图片的判定比文字弱？

因为 Jev 是纯文本决策模型，它的输入只能是文本，看不了图。所以图片走本地肤色像素启发式， 只有在「只发图/纯链接形态」下才用于隐藏成待确认，永远不会单独触发账号动作； 需要更强的图片判定可以在设置里另配一个支持图片输入的视觉模型端点。

我的数据会发到哪里？

只有推文文本与少量元数据（作者、位置、alt、卡片文案、本地肤色占比）会发给你自己配置的 Jev 网关； API Key 只保存在 chrome.storage.local 且只在后台 Service Worker 里使用；图片默认不出网； 可选的审计 webhook 默认关闭，开启后每条判定会 POST 一份事件。
