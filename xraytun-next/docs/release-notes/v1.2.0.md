# xraytun-next v1.2.0 · 仪表板对齐老版 XrayTun + 大启动按钮 + 只保留 TUN

**一句话**：这一版把仪表板按老版 XrayTun 的形状重建、新增全局顶栏与全屏唯一的大启动按钮，
并按用户 2026-10-01 裁决（T2）**只保留 TUN**（放弃直连与代理的产品面）。
**TUN 通路已宣告，但真机接管仍未经 S6 验收**——本版不发「TUN 能用」的声明。

## 改了什么

### 界面：仪表板按老版形状重建

- 仪表板按老版 XrayTun 的形状重排：**状态区 / 流量 / 提示横幅 / 诊断**四块回到原来的位置与层级。
- 新增**全局顶栏** `apps/ui/src/components/Topbar.tsx`：**只报状态，不放按钮**。
  依据是老版 task-72 的判据——同一动作同屏两颗只是重复，且两处禁用判据早晚会漂移。
- 新增**大启动按钮**（`data-testid="start-button"`）：仪表板顶部的**全屏唯一启动/停止控件**。
  逐字文案按状态给定（`disconnected` 无节点 / 未选节点 / 已选节点、`connecting`、`connected`、
  `disconnecting`、请求已受理、上次出错、`tun_mode` 未宣告），完整表见
  `docs/design/NEXT-VERSION-UI.md` §3.2。按钮可点性由 `capabilities` 是否宣告 `tun_mode`
  门控：未宣告则**禁用并说清真因**（这不是假控件，也**不是**把按钮藏起来假装功能不存在）。
- 界面**没有任何模式选择器**（无 `run-mode-select`），连接方式只有 TUN：`Connect` 恒发
  `mode: 'tun'`（`apps/ui/src/pages/Dashboard.tsx:122`）。

### 网速：UI 派生，绝不显示 `0 B/s`

- 速率 = `Δbytes / Δsampled_at_ms`，**必须有两个 `sampled_at_ms` 不同的样本**才显示；
  只有一个样本、或 `sampled_at_ms` 相同 ⇒ **不显示速率**
  （`apps/ui/src/components/trafficRate.ts`）。
  这是照抄项目既有口径（`docs/design/TRUE-INFORMATION.md`、`docs/ux/INTERACTION.md`），不是新发明。

### 守卫：`scripts/guard.sh` 唯一一处 I1 窄豁免

- 为**展示用采样节拍**（`apps/ui/src/store/daemon.ts:284` 的 `setInterval`）开了带标记的
  **窄豁免** `GUARD-EXEMPT(I1-UI)`。豁免**只对这一行生效**，不会把同文件里第二个定时器一起放行；
  guard **每次运行都把它打印出来**（`scripts/guard.sh:114-117`）。

### 后端：打开 TUN 通路

- `crates/xt-daemon/src/lib.rs`：删掉 `begin_connect_intent` 里「非 proxy 一律 `unsupported`」的早退。
- 能力表新增 `Capability::TunMode`（`hello()`）；另有 `ProxyMode / Stats / Probe / Subscriptions`。
  `SubscriptionFetch`（http/https 拉取）仍**不宣告**。
- TUN 通路本身早已写好：`crates/xt-daemon/src/flow.rs` 的 `connect_tun_flow`
  （helper `TunUp` → `TakeTunFd` → 以 `XRAY_TUN_FD` 拉起 xray → 就绪 → `CommitRoutes`）。
- 断言同步更新：`crates/xt-daemon/tests/e2e_real_xray.rs` 里「`TunMode` 不宣告」的旧断言改为宣告；
  **proxy 通路断言原样保留**。

### 没有改的东西

- `crates/xt-contract` 的类型**一行没改**（`RunMode::Tun` 与 `Capability::TunMode` 本来就在，
  见 `crates/xt-contract/src/model.rs`）⇒ 不碰冻结项。
- proxy 通路与 `RunMode::Proxy` **保留**：它是 CI 里**唯一能跑的真数据面**
  （`crates/xt-daemon/tests/e2e_real_xray.rs` 的真实进程 / 真实字节），`xt-cli` 继续用它。
  产品界面不再提供 proxy，但通路与无头入口不删。

## 诚实声明（不要跳过这一段）

- **TUN 通路已宣告 ≠ TUN 已验证可用。** 本版宣告的是「**本版本提供这条通路**」（代码事实）；
  **真机接管——helper 安装/回滚、utun 接管、路由与 DNS 提交——仍未经 S6 验收**，没有真机证据。
  任何「TUN 已工作 / 已可用 / 稳定」的说法**依旧不许出现**。
- 界面只提供 TUN ⇒ **非 macOS 平台上没有任何可用的连接方式**（proxy 入口已从产品界面移除；
  proxy 通路本身仍在，供 `xt-cli` 与 CI 使用）。
- 本版的验证只做到「**构建 / lint / 单测 / UI 验收**」这一层：`bash scripts/guard.sh` →
  `GUARD PASSED`（本次 `rust=53` / `ui=25` / `违规=0 警告=0`）；macOS CI（`macos-14`）覆盖
  构建 / lint / 单测 / UI，**不覆盖 TUN 接管**。开发机不是 macOS，且本仓库禁止在本机跑 cargo
  ⇒ TUN 真机路径在本机无法验证。
- 未经公证（没有 Developer ID 凭据）。Gatekeeper 拦下时：
  `xattr -dr com.apple.quarantine /Applications/XrayTun.app`

## 本版没有做

- 意图（过滤 / 分流）；
- 拓扑 / 地理可视化；
- 订阅远端拉取（http/https）——`SubscriptionFetch` 不宣告，界面无「添加 / 刷新」入口；
- 更新检查；
- helper 能力扩展：安装 / 回滚的真机验收、`restore_stale` 快照还原等仍无证据
  （见 `docs/architecture/00-CONTRACT-FREEZE.md` §6、`docs/product/NON-GOALS.md` §1.2）。
