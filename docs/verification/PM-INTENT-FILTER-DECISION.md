> 角色：产品经理（不写产品代码）。

> `docs/release-notes/v0.8.38.md`、`docs/release-notes/v0.8.39.md`，以及相关代码的静态阅读。
> **本文没有独立复跑任何评测**：所有数字都是引用仓库内既有文档（引用到文件 + 小节/行号），
> 我的独立判断都标成"判断"，不确定的写"没验证"（见文末）。

## 结论 + 证据链接

**建议：暂停（Pause）** —— 保留代码与界面，维持 **默认关闭 + 演练模式**；**冻结**对 L1 模型
增量价值（"发现静态名单之外的新广告域"）的进一步投入；在跑完 §5 的一轮实验之前，
**不允许默认开启**，也不允许把 MITM 内容层作为"能过滤广告"的新增卖点推进。
保留/砍掉的判定权交给 §2 里写死的闸门与杀条件（可证伪，不需要再开会）。

证据链（每条都指向文件 + 小节）：

* 唯一被数据支持的结论是"**开它不太会误杀**"：精确率 **1.000**（累计 7 真阳 / 0 假阳）、
  误杀 **0.000 / 1000 连接**（累计 100 个强负样本全放行）——`docs/verification/INTENT-EVAL-BASELINE.md` §3.4。
* 但**本功能的全部增量 = 0**：无标注桶 **0 / 96**（两次独立运行），
  而且**把三个闸门全放开仍是 0 / 48**——同文件 §3.3.1、§3.4。
* 已知广告域召回只有 **1/3 ~ 2/3**（§3.1 = 0.417、§3.2.1 = 0.333、§3.3.1 = 0.667）——同文件 §3.4。
* 真正在干活的是 **L0 静态名单**：覆盖 **0.78% 的连接 / 4.2% 的域名**，
  而 **63.2% 的连接行配不到域名**（再准的模型也用不上）——同文件 §2。
* 评测工具本身会量错：紧循环会把免密钥档额度打满，**量到的是配额不是模型**（第二轮 106 候选 / 93 无答案）——同文件 §3.2。
* 全部模型数字来自免密钥档 `jev-1.13-free`（同文件 §3），而**产品默认预设是 `Typesafe`（需要 Key）**——
  `crates/xt-core/src/model.rs:731-739`。也就是说：**产品默认路径上的模型从来没被量过**。

## 1. 为什么是"暂停"，而不是"保留"或"砍掉"

| 选项 | 含义 | 支持它的理由 | 反对它的理由 | 结论 |
|---|---|---|---|---|
| **保留**（继续投入 → 默认开） | 继续开发 L1/MITM，达到判据就默认开启 | 精确率/误杀率判据已"通过"（§3.4） | 判据只覆盖"会不会搞坏上网"，不覆盖"有没有用"（§3.4 结论 2）；增量 0/96（§3.4）。默认开 = 让所有用户把访问域名发给第三方网关，换取 0 增量 | ❌ 现在不成立 |
| **砍掉**（删功能/删代码） | 移除意图过滤（含评测夹具） | 增量没有证据；维护面不小（§3.3） | 功能已**默认关闭 + 演练**（`crates/xt-core/src/model.rs:891-895`、`947-965`），今天的用户暴露 = 0；而且删掉会顺带删掉唯一能回答"是不是模型不行"的评测夹具（`crates/xt-intent/src/eval.rs`），而验证它只要一轮（§5） | ❌ 太早 |
| **暂停**（推荐） | 不默认开、**冻结新增投入**，保留默认关闭 + 演练与评测夹具，按 §2 闸门决定去向 | 暴露为 0；保留唯一低成本的证伪手段；把"值不值得"变成一次可执行实验 | 需要防止"暂停 = 事实上保留" | ✅ **建议** |

**"暂停"的边界（避免它变成无限期悬置）：**

1. 不再新增 L1 / MITM 功能；只允许修 bug 与安全/隐私问题（哪些算安全由安全审计定）。
2. 对外文案不得出现"能过滤广告 / 发现新广告域"这类承诺（`docs/release-notes/v0.8.38.md` 第 18-21 行已经是正确写法，保持）。
3. 时限：跑完 §5 的一轮实验后 **1 周内**出"转保留 / 转砍掉"的决定。
4. L0（`preset-ads`）与意图过滤分开评估：L0 的 0.78% 覆盖是独立的、已经被测到的产出，不受本决定影响。

## 2. 可证伪的判据

### 2.1 N 是怎么来的（不是拍的）

已知的基线：无标注桶 **0 block / 96 次判定**（两次独立运行合计，§3.4），
且**放宽到全放开阈值仍是 0 / 48**（§3.3.1）——也就是说，在 96 次机会里模型一次都没抓。

统计上，**n 次试验里 0 次事件时，真实比率的 95% 单侧上界 ≈ 3/n**（教科书 "rule of three"，
95% 置信）。取基线 n₀ = 96，得到比率下界参考

```
p* = 3 / 96 = 3.125%
```

于是"增量存在"的最小证据量是：新一次**干净**运行里，无标注桶的 block 数 ≥ ⌈p* × n⌉。

| 新运行的无标注桶条数 n | 要求的最少 block 数 N = ⌈3.125% × n⌉ |
|---|---|
| 96 | **3** |
| 120 | **4** |
| 138 | **5** |

**N 的含义要说清**：它只表示"这次观测到的比率不低于旧观测 0/96 的 95% 上界"，
即"不是把旧的 0 当成噪声重报一遍"。它**不是**"证明有用"的门槛 —— 有用要过下面的 Gate B。
3 这个数字的另一层理由：单条命中可能是误判或偶发，≥3 条才谈得上"一个现象"。

> 说明：`rule of three` 是我引入的决策门槛，仓库里没有既有判据（见文末"没能验证"）。
> 如果评审不接受这个门槛，N 需要由评审重新定；但"必须有一个前置 N"这件事本身是硬的。

### 2.2 三条闸门

**Gate A（增量存在）** —— 用**产品默认预设**（`Typesafe` + Key；`crates/xt-core/src/model.rs:731-734`）
或等价强模型，在一次/连续窗口的限速运行里同时满足：

| # | 条件 | 为什么 |
|---|---|---|
| a | 无标注桶 **n ≥ 96** 且**拿不到答案 = 0** | §3.2 的教训：有 `deferred` 时"0 拦"不可解释（可能是没问到） |
| b | 无标注桶 **block ≥ N**（§2.1 表） | 增量存在的证据；这是本功能的全部增量（§3.4） |
| c | 强负样本**误杀 = 0** | 基线实测是 0/100（§3.4），比设计 §10-P1.5 的 ≤1/1000 更严；误杀代价不对称（§3.3） |
| d | 人工抽查：被拦的未知域名**至少 2/3** 确认为广告/追踪基础设施 | 未知桶没有 ground truth，只能人看（§3.3"还缺"）；允许 1/3 判错是给模型留余量，不可放宽到"全对" |

**Gate B（对人有价值）** —— 设计 §10 的 P4 判据里那条"真实站点开关前后对比（广告请求数下降）"，
目前在 §16.7 里明确标着 **❌ 未做**；同时误杀维持 ≤ 1/1000 连接（§10-P1.5）。

**只有 Gate A + Gate B 同时过，"默认开启"才成立。** Gate A 通过只解锁"演练态影子跑一周"。

**杀条件（同样可证伪）** —— 在 a（n ≥ 96、unanswered = 0）满足的前提下，
如果 **b 不满足（block ≤ N-1）**：**转砍掉** —— 至少砍掉 L1 的"增量"价值主张与全部相关对外文案，
保留 L0 与评测夹具。**不允许重跑挑好看的一次**；unanswered > 0 的运行按 §3.2 判为无效并重跑，
既不读成 0，也不算通过。

### 2.3 明确**不接受**的替代证据（防止绿灯被误读）

* **"判据通过"**（精确率/误杀率）只说明"不太会搞坏上网"，不说明有用（§3.4 结论 2）。
* **提高已知广告召回**（例如 `ads_intent_min` 0.85 → 0.5，召回 0.333 → 0.667，§3.3.1 末段）**不解决增量**：
  那批域名静态名单本来就覆盖（§2 表）。所以**不为了"看起来有用"而降低阈值**；阈值改动只能作为
  Gate A 实验里的对照，不能当成上线依据。
* **小样本**（如 §3.2 的 8 正 / 14 负，精确率 1.000）样本太小，不作为判据（§3.2 自己注明"只有 8 正 14 负有答案"）。

### 3.4 用户认知负担

| 项 | 事实 | 证据 |
|---|---|---|
| 上手成本 | 默认关闭 → 用户自己开 → 默认演练（只记录不拦）→ 看几天审计 → 关演练 → 手动点"应用到核心" | `docs/release-notes/v0.8.38.md` 第 13-23 行；设计 §7.5；§16 P2b-2 边界 |
| **"打开了却没效果"** | 开启后：已知广告域只有约 **1/3~2/3** 被拦（§3.4），静态名单之外的**新域名一条都不拦（0/96）**。用户的主观体验与"功能坏了"无法区分 | 基线 §3.3、§3.4 |
| 第二层误解 | "打开拦截" ≠ "规则已生效"：规则只在**核心启动时**下发，界面必须说"待生效"而不是"已在拦截" | 设计 §16 P2b-2 边界 |
| 正确的做法（保持） | v0.8.38 的 notes 已如实写出"本版不把它说成'打开就能过滤广告'" | `docs/release-notes/v0.8.38.md` 第 18-21 行 |

**判断**：这是**反对"现在默认开"最强的一条理由**——不是它有害，而是它**会让人以为它有用**。
产品上，一个默认关闭、打开后看不出一丝变化的开关，最好的结局是没人打开；最坏的结局是
用户以为"我在过滤广告了"而放松了别的防护。

## 4. 对用户原始诉求的诚实回答："在 TCP/UDP 层拦广告"现在实际能拦到什么

**一句话**：今天实际能拦到的是**静态广告名单那一层，约 0.78% 的连接**；
"意图过滤"（模型）这一层**没有可测的净增量（0/96）**。
所以"打开意图过滤就能过滤广告"是错的；"静态广告名单一直在拦一小部分广告"是对的。

| 分类 | 实测/机制 | 证据 |
|---|---|---|
| **能拦到**：第三方投放 / 追踪端点 | L0 静态名单（`geosite:category-ads-all`，即现有 `preset-ads`）覆盖 **0.78% 的连接 / 4.2% 的域名**；它不依赖模型 | 基线 §2 |
| **能拦到**：TCP/UDP 的**机制** | 数据面验收已通过：TCP 对照 200 / 实验 403；UDP 四组对照（含 `block-silent` 真静默）——**管道是通的** | 设计 §16「数据面验收」、§16.7 |
| **拦不到**：63.2% 的连接行 | 配不到域名（比模块文档记的 ~52% 更高）⇒ 再准的模型也用不上 | 基线 §2 |
| **拦不到**：静态名单之外的新广告域 | 无标注桶 **0/96**；三阈值全放开仍 **0/48** ⇒ **"发现新广告域"目前 = 0** | 基线 §3.3.1、§3.4 |
| **拦不到**：已知广告域的多数 | 召回只有 **1/3 ~ 2/3**（这部分还与 L0 重叠，所以净增量还要更低） | 基线 §3.4、§3.3.1 |
| **拦不到**：同域广告（X 推广帖、YouTube 前贴片、B 站推荐位） | 字节来自主站，拦域名 = 拦主站；**只有 MITM 能到内容层**，且 MITM 只对用户逐个点名的域名拆 | 设计 §0、§1.2；`docs/release-notes/v0.8.38.md` 第 25-33 行 |
| **拦不到**：TLS 里的 URL / Header / Body（约 95% 流量） | L1 只能看 SNI / Host / QUIC SNI / 明文 DNS 查询名 | 设计 §1.1 |
| **"静默"也不是全静默** | 域名级意图拦截规则（TCP+UDP 混合）在 UDP 上**仍回 403 字节**；只有 UDP-only 规则（QUIC 兜底）真静默 | 设计 §16.1、§8.4 |
| **首访还会看到广告** | 未命中缓存的域名在判决回来前**必须放行**（"首访放行"），这是设计不是 bug | 设计 §14、§11 |
| **ECH / DoH 会继续削弱能力** | ECH 下只能拿到外层 SNI；浏览器 DoH 会让 DNS 层拦截失效，退化为 SNI/IP | 设计 §1.1、§11 |

## 5. 下一步最小实验（一轮内跑完、且能改变决策）

**实验**：用**产品默认预设**（`Typesafe` + Key；`crates/xt-core/src/model.rs:731-734）在**限速**下
重跑**无标注桶全覆盖**，与免密钥档的 0/96 对比。

**为什么是这个实验**：全部模型证据来自免密钥 `zen` 档（基线 §3），而**产品默认预设是 `Typesafe`**——
"换强模型"这条路的第一个未知量就是"默认预设到底行不行"，而它**从未被量过**。
它恰好也是一轮能跑完的：基线 §3.3 给的同规模长跑是"约 120 条 × 1.2s ≈ 2.5 分钟"。

**怎么跑**（基线 §1 的 ② + 默认限速；确切参数名以 `eval_domains --help` 为准，
下面只保证有 `--corpus` / `--live` / `--limit` / `--sleep-ms`，见基线 §1、§3.3.1）：

```bash
CORPUS="$HOME/Library/Application Support/com.xraytun.desktop/logs"
cargo run -q -p xt-intent --example eval_domains -- \
  --corpus "$CORPUS/app.jsonl" --corpus "$CORPUS/app.1.jsonl" \
  --geosite-dir apps/desktop/binaries --report /tmp/intent-eval-typesafe.md \
  --live --limit 140            # 默认 --sleep-ms 1200（基线 §3.2）
```

**判决规则（必须写在跑之前，避免事后挑数）**：

| 观测 | 判读 |
|---|---|
| n≥96、unanswered=0、block ≥ N（§2.1）、FP = 0 | **Gate A 通过** → 转"演练态影子跑 + Gate B 真实站点对比" |
| unanswered = 0、block ≤ N-1 | **Gate A 失败** → **转砍掉**（至少砍掉 L1 增量主张与全部相关文案） |
| unanswered > 0 | **本次运行无效**（量到的是配额不是模型，基线 §3.2）→ 限速后重跑；**不得读成 0，也不得算通过** |

**成本**：一次 Key 配置 + 一次运行（约 140 × 1.2s ≈ 3 分钟）+ 人工抽查。
抽查要用 `--dump-unknown` 导出被拦域名——**那批是浏览记录，只能导到仓库外**（基线 §3.3、§5）。

**为什么它能改变决策**：它是唯一能把"值不值得继续"从"没有证据"变成"有/没有证据"的动作。
通过 → 暂停转保留；失败 → 暂停转砍掉。除此之外的争论（阈值、提示词、MITM 卖点）都排在它后面。

## Lead 评审（裁决 + 两处事实订正）

**裁决 1：批准 `rule of three` 作为 N 的来源。** 理由：基线是"0 block / 96 次"，观测到 0 次时
单侧 95% 上界约 3/n，所以"下一次在同规模语料上至少出现 3 条 block"是把"增量存在"证伪/证实
的最小门槛，且它**可复算**（`p*=3/96`，n=120→4、138→5）。这是 Lead 引入的门槛、不是仓库既有判据，
所以在这里**显式记为裁决**，而不是让它藏在报告的"我没能验证的"里。

**裁决 1 的附加条件**（缺一条该次运行即作废、不算证据）：
1. **限速运行**（`--sleep-ms 1200` 起）且 **`unanswered = 0`** —— 否则量到的是配额不是模型；
2. 记录**预设 + 模型 id + 是否有 Key**，并写明语料窗口（日志会轮转，前后两次的语料不是同一份）；
3. 判决规则**跑之前写死**（不得看到结果再改 N）。

**裁决 2：`Typesafe`（产品默认预设）从未被量过** —— 现有全部数字来自免密钥的 zen 档。
所以"默认预设下的无标注桶覆盖"是正确的下一个实验。**但它需要 Key**：没有 Key 就跑不了，
而"暂停"状态在拿到这个数字之前不应改变。这一点要在下一次评审时明确谁来提供 Key。

### 两处事实订正（对报告正文）

1. **§9 的"外发前过一次本地过滤"是存在的**，只是不在桌面层：
   `crates/xt-intent/src/observer.rs:218` 调 `is_candidate(host, inbound_tag, port, &allow_hosts)`，
   而 `allow_hosts` 由 `crates/xt-intent/src/engine.rs:207` 与 `:257` 注入。
   该函数负责挡掉 IP 字面量 / 内网 / 单标签 / 白名单（相关分支有测试，如 `:511`、`:519`）。
   ⇒ 报告里"是否真的存在"这条疑问**已由 Lead 复核，结论是存在**。
2. **"进程名已过期"这条成立，且要修的是设计文档**：`FlowContext.process` 是 `Option<String>`
   （`question.rs:200`，注释明写"拿不到就 None，不要编"），只有拿到时才拼进问题
   （`:282-283`）。生产路径目前拿不到进程名 ⇒ **设计 §9 表里"外发字段含进程名"这句是错的**，
   应删掉或标注"取决于能否取到"。这是文档欠账，不是实现 bug —— 但对外承诺的外发字段清单
   必须与实际一致，所以它必须修。

## Lead 最终裁决（2026-09-25）：**按 PM 的杀条件转「砍掉」路线**

触发依据（两个独立运行，都由 Lead 亲自复核过报告原文）：

| 运行 | 模型 | 无标注桶 | 判据 N（rule of three） | 结果 |
|---|---|---|---|---|
| 免密钥档 | `jev-1.13-free`（zen） | **0 / 96** 拦 | n=96 → N=3 | 0 ≤ N-1 ⇒ **触及杀条件** |
| 付费强模型 | `jev-latest`（TypeSafe，产品默认预设与阈值） | **0 / 149** 拦，`unanswered=0` | n=149 → N=5 | 0 ≤ N-1 ⇒ **触及杀条件** |

两条都满足"限速 + unanswered=0"，所以这不是配额问题、不是阈值问题（全放开仍是 0/48）、
也不是"免密钥档太弱"——**换到付费强模型、用产品默认预设，增量依然是 0**。
而本功能的全部价值就在那一桶（静态名单拦不到的新域名）：L0 静态名单覆盖的
连接占比实测只有 **0.78% ~ 1.43%**，模型没有加出任何一条。

**裁决内容**（不是删代码）：
1. **停止一切新增投入**；默认关闭 + 演练模式**锁死**（`IntentSettings::default` 不得改）；
2. **文案与发布说明不得再承诺广告拦截**；对外说法只能是"实验性、已验证无增量"；
3. 唯一复起前提：**改问题/提示词后重过同一套判据**（同一语料窗口、限速、`unanswered=0`、
   按 rule of three 的 N）；复起失败则删除 `xt-intent` 与 MITM 的引导链路；
4. **不受影响、继续维护的部分**：MITM 通道本身（TLS 终结/回写/体裁剪）与信任锚基础设施 ——
   它们是"内容级处理"的通用能力，与"谁来判"无关；本轮在其上修掉的两条 P0 必须保留。

**为什么不是"删掉"**：用户暴露为 0（默认关闭 + 演练），而它是目前唯一能**证伪**
"模型能不能发现新广告域"的夹具；删掉等于把这个已经量出来的否证结论也一起丢掉。
