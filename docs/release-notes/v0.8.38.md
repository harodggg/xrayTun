## 这一版修了什么（都已在 v0.8.37 之后落地，本版才送到你机器上）

* **日志不再无界增长**。以前轮转**事实上每个 App 进程只跑一次**（高频写入路径不做超限检查），
  实测 `app.jsonl` 涨到 **311.8 MiB/天**、单文件到 96 MiB。现在按**字节预算**触发修剪且改为
  **零拷贝**：磁盘上界 **≤ 160 MiB**、按实测速率（116 / 312 / 612 MiB/天）的保证窗口是
  **9.8 – 48.8 h**。**代价**：修剪仍在日志写入路径上，可能造成**一次短暂停顿**。
* **「国内全灭、国外正常」现在会自愈**。以前境内侧只有 **1 个**探测目标，而重建门槛是
  「一轮 ≥2 个目标失败」⇒ 境内全灭**永远到不了门槛、永不重建**（用户 2026-09-24 11:43 的现场
  就是这个形状）。现在境内侧有 **2 个**目标 ⇒ 会触发重建。**代价**：启动门禁在最坏情况下
  多一个境内目标的失败路径（量级 18 s → 24 s，由 Lead 给出；我未实测端到端）。
  另外删掉了「探测目标」的第二份真源：新增目标漏登记**编译不过**，不会再被静默算成「境外」。
* **「国内不通」下次可以**直接判读**了**。App 现在会把「en0 的作用域默认路由
  （`default … UGScIg en0`）在不在」按**采样时点**（接管前 / 接管后 / 回滚后 / 看门狗状态变化）
  写进落盘日志。这是**只读**审计：它回答「那条路由在不在」，**不回答「是谁装的」**
  （别的 VPN 工具也在写同一张表）—— 所以它能把 `task-172` 的主假设从「推断」变成「可判读」，
  但不能单独定罪。

## 诚实边界

* 真机安装 / 重启 / Gatekeeper **未在本环境验证**；本环境也不在中国大陆，GFW 行为无法复现；
* 「日志上界 160 MiB」与「保证窗口 9.8–48.8 h」是**按实测写入速率推算**的（推导见
  `docs/verification/NET-METRICS.md` §10），**不是**等了一整天测出来的；
* 「国内全灭会自愈」验证到的是**门槛逻辑 + 探针可达性**；**用户现场那条链路未复现**；
* 本版还把一条**已存在的**缺陷形状固化成了断言（v6 节点旁路退化成**无网关 on-link**）——
  那是**记录事实**，**不是修复**；修法是后续版本的事。
