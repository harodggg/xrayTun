## 给用户的动作：**本版需要重新安装特权助手（一次管理员授权）**

**为什么必须**：App 升级**不会**刷新特权 helper —— `restart_helper` 只是 `kickstart` 磁盘上已经装着的那份二进制，
只有「重新安装助手」才会把包内那份拷过去。而**路由与 DNS 的安装/回滚都发生在 helper 里**，
所以不重装，本版的两个网络修复（下面第 1、2 条）**一点都不会生效，而且完全无声**。

怎么判断"该重装了"（可复算）：

```bash
git diff --stat v0.8.42..v0.8.43 -- crates/xt-helper crates/xt-proto   # 非空 ⇒ helper 行为变了
git show v0.8.43:crates/xt-proto/src/lib.rs | grep PROTOCOL_VERSION    # = 3（v0.8.42 是 2）
```

本版把 `PROTOCOL_VERSION` 2 → 3，并把它明确定义为 **App ↔ helper 的「行为契约」版本**：
helper 侧行为一变就必须升，否则老 helper 会被判成"匹配"，用户更新了 App 却拿不到修复。
界面据此会提示「重新安装助手」，装上之后两个修复才真正生效。

## 这一版修的是：**App 失败/回滚之后，不再影响你整机的网络**

### 1. 系统 DNS 不再残留成死地址（「终端不通、浏览器有时候通」的真凶）

- 连上时我们会把 Wi-Fi 的 DNS 设成假 IP 网关 `198.18.0.2`。从前清理**只在会话被判定为 stale 时**发生，
  而判定看的是快照里的状态标志位；helper 重启/重装而 App 不在时**没人清理** ⇒
  **整机解析不了任何域名**（浏览器带 DoH 时有时还能通，终端几乎一定失败）。
- 现在：判据从"标志位"改成"**会话是否真的还活着**"——快照里记的那个 `utun` 接口**此刻是否还存在**
  （只读探测；探测不到就一律不动，宁可漏清也不误拆在用隧道）。
  启动即对账：发现「接口已不在 **且** DNS 还是 `198.18.0.2`」就恢复——有原值还原原值，没有则清成 DHCP。
- 同时修掉一个会让问题**永久化**的陷阱：备份**从不**把哨兵地址当成"你的原值"。
  即使磁盘上已存着被旧版写坏的备份（`servers:["198.18.0.2"]`），本版也能把它救回来。
- 恢复之后**立即复检**（逐服务比对期望值/实际值），失败不假装成功。

### 2. 回滚不再"假报成功"

以前只要恢复命令发出去了就写「已回滚」，命令静默失败也照样报成功。现在回滚必须**复检三项**才敢说成功：

1. 默认路由查得到、带网关、且不在我们的 utun 上（真的没有默认路由时按快照网关 fail-open 重装一次）；
2. **本次会话自己的** `0/1`、`128/1` 捕获路由不许还挂在我们的 utun 上（这是整机黑洞的真正入口）；
3. 每个改过的服务 DNS **逐值等于备份的原值**（含"原本没有设置"= 走 DHCP 这一态）。

任一不过 ⇒ **点名**哪条路由/哪个服务的 DNS、期望值与实际值，保留快照等下次重试。

### 3. 连接失败时不再只说一个节点、也不再让你先去换网络

- 回落成功时会**点名**："本次实际使用了哪个节点、为什么换、**你的选择没有被改动**"；
- 全部失败/退回直连时给出**节点级清单**：名字 + `地址:端口` + 失败类别 + 耗时 + 下一步；
  若有节点 TCP 可达，会用证据写明"**本机网络本身没问题**"，而不是让你去怀疑自己的网；
- 「换一个网络」只在"整台 Mac 直连也不通"时才作为建议，并且排在最后。

> 诚实边界：App **不能**让一个不可达的节点变得可达。这一版保证的是：不接管默认路由、不让你猜、
> 不只试一个节点、并且把"实际用了哪个、为什么换"说清楚。

### 4. 附带（默认关闭，尚未接入界面）

MITM「**只观察、不改写**」模式：可以把带 body 的请求与 chunked 响应**逐字节原样**透传，同时只记录摘要
（host / 路径 / 类型 / 字节数 / 短哈希 + 广告标记词命中计数），**默认不落盘任何正文**。
它的用途是回答"广告响应里到底有没有机器可读标记"——先有数据，再决定用确定性规则还是模型。
当前只是库层能力与配置结构，界面入口在下一版。
