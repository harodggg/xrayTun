# 意图过滤 · 离线评测基线（P1.5）

> 这份档案记录**已经量到的**与**还量不到的**。两者分得很清楚 ——
> 因为"模型准不准"正是这个功能能不能默认开启的唯一依据。
>
> 时间：2026-09-24（语料是**正在写入**的本机日志，所以每次跑数字都会略有变化）
> 工具：`crates/xt-intent/examples/eval_domains.rs`（逻辑在 `crates/xt-intent/src/eval.rs`，有 9 条单测）

## 1. 怎么复跑

```bash
cd xray-tun
CORPUS="$HOME/Library/Application Support/com.xraytun.desktop/logs"

# ① 只算 L0 静态名单的覆盖：不联网、不需要模型
cargo run -q -p xt-intent --example eval_domains -- \
  --corpus "$CORPUS/app.jsonl" --corpus "$CORPUS/app.1.jsonl" \
  --geosite-dir apps/desktop/binaries --report /tmp/intent-eval.md

# ② 带上模型（需要一个能问通的 Jev 网关）
cargo run -q -p xt-intent --example eval_domains -- \
  --corpus "$CORPUS/app.jsonl" --geosite-dir apps/desktop/binaries \
  --report /tmp/intent-eval-live.md --live --limit 200
```

## 2. 已经量到的（L0 基线，本机真实语料）

| 项 | 实测 |
|---|---|
| 读入日志行 | 163,870 |
| 连接行（分母） | **16,634** |
| 其中**配不到域名** | 10,507（**63.2%**） |
| 观测到的域名 | 259 |
| ├ 命中 `category-ads-all`（强正样本） | 11 |
| ├ 命中明确产品表（强负样本） | 110 |
| └ **无标注（模型要判的那批）** | **138** |
| 被观察器过滤掉（IP 字面量/内网/单标签…） | 2 |
| **静态名单覆盖的连接占比** | **0.78%** |
| 静态名单覆盖的域名占比 | 4.2% |

**三条能直接下结论的事：**

1. **现状（`preset-ads` 静态名单）拦到的流量不到 1%。** 也就是说
   "意图过滤"这个功能的全部价值，落在那 **138 个没有标注的域名**上 ——
   静态名单该拦的都拦了，剩下的要么是它不认识的新域名，要么是大厂自营域。
2. **63.2% 的连接行配不到域名**（比 `access_log` 模块文档里记的 ~52% 更高）。
   这是能力上限的直接约束：**再多智能也用不上没有域名的连接**。
   这个数应该作为一个常看的指标（`PairingStats` 已经有了），而不是一次性的观察。
3. **域名数量很小**（259 个 / 1.6 万条连接）。这意味着"每域名问一次"的成本
   在真实使用量级上完全可接受 —— 预算默认值（10/分钟、200/天）有一到两个数量级的余量。

## 3. 还量不到的（以及为什么）

**模型指标全部缺失。** 本次尝试的两次运行都是 `deferred`，原因分布明确：

```text
拿不到答案的原因分布：gateway_errors=12、budget_denied=42
```

`gateway_errors` 的来源是 HTTP **429**：
`{"type":"error","error":{"type":"FreeUsageLimitError","message":"Rate limit exceeded. Please try again later."}}`
（OpenCode Zen 免密钥档，本机当前额度已被用尽；返回的是结构化的限流错误，**不是** 401，
所以"免密钥可用"这一点仍然成立，只是此刻没有额度。）

要拿到模型指标，需要下面任一条：

* 一个 TypeSafe API Key（`--api-key` 或 `JEV_API_KEY` 环境变量）；或
* 免密钥档恢复额度后重跑 ②；或
* 自建/其它兼容网关（`--base-url` + `--model`）。

**在拿到数字之前，功能保持默认关闭 + 演练模式**（设计文档 §10 的 P1.5 判据：
holdout 精确率 ≥ 0.95 且误杀 ≤ 1/1000 连接）。这不是保守，是因为误杀的代价不对称 ——
漏一个广告用户无感，误杀一个正常站点用户会立刻关掉功能。

## 4. 这次刻意做的两个"不许骗人"的规则（都有单测）

* **分母为 0 时不许打印 `0.000`**：报告里三处比率在无样本时显示
  `—（没有一条可验证的 block 判定）` 这种带原因的破折号。
  `0.000` 看起来像"测出来的零"，实际是"根本没测" —— 这个区别决定了报告能不能被相信。
* **未知桶里的 block 不计入精确率分子**：那正是我们要量的东西，拿它去证明自己准是循环论证。
  报告如实把它单列一行（`无标注桶里被拦`）。

## 5. 隐私

* 报告**只有聚合数字**，没有任何域名；有一条单测直接断言"报告里不许出现测试域名"。
* 语料是用户的浏览记录，因此 `--dump-unknown <path>`（导出域名列表）**默认关闭**，
  且提示要导到仓库之外。
* 评测只读日志文件，不起核心、不改任何系统配置、不外发任何东西（除非显式 `--live`）。

## 3. 已经量到的（**模型指标**，2026-09-25 免密钥档恢复额度后）

第一次跑通是在免密钥的 **OpenCode Zen** 档（`jev-1.13-free`）—— 免费额度是本功能
唯一的外部依赖，本机实测它**有时是 429**（2026-09-24 那次就是），2026-09-25 恢复。

两次运行的原始报告在 `/tmp/intent-eval-live.md` 与 `/tmp/intent-eval-full.md`（都在仓库外）。
报告里**只有聚合数字**，域名要用 `--dump-unknown` 显式导出。

### 3.1 第一次（可用）：120 条候选

| 项 | 实测 |
|---|---|
| 连接行（分母） | 14,677 |
| 其中配不到域名 | 10,757（**73.3%**） |
| 观测域名 | 210 |
| ├ 强正样本（命中 `category-ads-all`） | 12 |
| ├ 强负样本（命中 apple/microsoft/google/category-gov-us） | 76 |
| └ 无标注（模型要判的） | 122 |
| 真阳性 / 假阳性 / 假阴性 / 真阴性 | **5 / 0 / 7 / 60** |
| 无标注桶里被拦 | **0** |
| 拿不到答案（放行） | 36（`gateway_errors=36`、`budget_denied=138`） |
| **精确率** | **1.000**（判据 ≥ 0.95） |
| **误杀率** | **0.000 / 1000 连接**（判据 ≤ 1） |
| **召回率** | **0.417**（非判据） |
| 报告的结论 | 通过（按写死的判据） |

**12 个正样本与 60 个负样本全都拿到了答案**，所以精确率与误杀率这两个数**可用**；
无答案的 36 条落在无标注桶里，不影响判据。

### 3.2 第二次（**不可用，而且不可用本身是结论**）：请求 210 条

| 项 | 实测 |
|---|---|
| 候选 | 106 |
| 拿不到答案 | **93**（`gateway_errors=196`、`budget_denied=361`） |
| 精确率 / 误杀率 / 召回率 | 1.000 / 0.000 / 0.714（**只有 8 正 14 负有答案，样本太小**） |

紧循环接在第一次后面跑，把免密钥档的额度打满了。**这不是模型的锅，是评测工具的锅**：
量到的是配额，不是准确率。所以 `eval_domains` 现在默认 `--sleep-ms 1200`
（约 50 次/分钟），要关掉得显式写 `--sleep-ms 0`。
**任何"Jev 准不准"的结论都必须来自限速运行。**

### 3.2.1 第三次（**限速、0 条无答案 —— 结论最干净的一次**）

限速跑通了，于是"拿不到答案"变成 **0**：问出去的每一条都拿到了模型的真实判决。

| 项 | 实测 |
|---|---|
| 观测域名 / 连接行 | 141 / 9,144（其中配不到域名 76.4%） |
| 强正样本 | 6 → 真阳 **2** / 假阴 **4**（召回 **0.333**） |
| 强负样本 | 40 → 真阴 **40** / 假阳 **0**（误杀率 **0.000**） |
| **无标注桶** | 问了 **48** 条，**被拦 0 条**，拿不到答案 **0** 条 |

**这一条把最关键的问题答清了**：无标注桶里 **0 条 block，而且不是"没问到"** ——
48 条全部拿到了答案，模型的回答统一是"不是广告"。加上第一次那 48 条同样为 0，
**两次独立运行、近百个静态名单拦不到的真实域名，模型一条都没认定为广告。**

### 3.3 这份数字支持什么、不支持什么（**别读成"能过滤广告了"**）

* **支持**：「开启它**不太会误杀**」。60 个明确正常的域名（Apple/微软/谷歌/美国政府域）
  一个都没被误杀；静态名单命中的广告域也没有被放过（0 假阳性）。
* **支持**：「**召回很低**」。已知广告域 12 个里只拦到 5 个（41.7%）。
  这不是判据（设计刻意只把精确率与误杀率当准入门槛：漏拦广告用户无感，
  误杀正常站点用户会立刻关掉功能），但它是**产出量**的直接度量 ——
  打开这个功能，**已知**的广告域名里大约只有四成真的会被拦住。
* **不支持**：「模型能发现新广告域」。**无标注桶里一条都没被拦** ——
  而这**正是这个功能的全部增量**（静态名单拦不到的那批新域名）与网关账单的去处。
  本次评测对这一件事**没有任何证据**。要支持它，未知桶里必须至少有几条真的 block。
* **还缺**：一次**限速的、覆盖全部无标注域名**的长跑（约 120 条 × 1.2s ≈ 2.5 分钟，
  但要避开额度窗口），以及一条**人工抽查**：把模型拦下的未知域名逐条看一遍
  （它们无法自动验证，所以只能人看）。

### 3.3.1 **阈值不是原因**：把三个闸门全放开，无标注桶仍然是 0

无标注桶 0 拦有两种解释：**闸门太保守**，或者**模型根本不给那个概率**。
这两件事的处理方式完全不同（前者调阈值，后者换模型/改问题），所以必须把闸门全放开再量一次。
`eval_domains` 现在有 `--ads-min` / `--risk-max` / `--choice-min` 三个旋钮（默认等于产品默认值，
报告里会写明用了哪一组，否则两份数字放一起没法比）。

| 闸门设置 | 已知广告召回 | 强负样本误杀 | **无标注桶被拦** |
|---|---|---|---|
| 产品默认（0.85 / 0.3 / 0.5） | 0.333（2/6） | 0 | **0 / 48** |
| 松一档（0.5 / 0.6 / 0.5） | 0.667（4/6） | 0 | **0 / 48** |
| **全放开**（0.2 / 0.9 / 0.05） | 0.667（4/6） | 0 | **0 / 48** |

**三条结论（都有数字，不是推理）**：

1. **不是阈值问题。** `ads_intent_min` 压到 0.2、置信度下限压到 0.05、风险刹车放到 0.9，
   无标注桶**一条 block 都没有** ⇒ 模型对这些真实域名**根本没有给出「是广告」的高概率**
   （或被判进了别的类别），不是被闸门挡住的。
2. **连已知广告域都只拦到 4/6。** 剩下 2 个在"全放开"的设置下**仍不被定罪** ⇒
   模型判断与 `geosite:category-ads-all` 在约三分之一样本上不一致。
3. **所以「复用 Jev 发现新广告域」这条价值主张，在免密钥档（`jev-1.13-free`）上
   没有任何证据支持。** 要救它只有两条路：换更强的模型（TypeSafe 等预设需要 Key），
   或改问题/提示词（那是独立一步，而且**改完必须重新量**）。

**一个可以独立评估的产品旋钮**（与上面的结论分开看）：把 `ads_intent_min` 从 0.85 降到 0.5，
已知广告召回从 0.33 → 0.67，而**误杀仍是 0**。它只提高"已知广告"的召回 ——
而那批域名静态名单本来就覆盖，所以它不解决增量问题，但可能值得单独看。

### 3.4 三次运行合起来说明什么（**这条要写进决策，不是写在附录里**）

| 事实 | 数字 | 含义 |
|---|---|---|
| 精确率 | 1.000（累计 7 真阳 / 0 假阳） | 开它**不太会误杀** —— 这是唯一被支持的结论 |
| 误杀率 | 0.000 / 1000 连接（累计 100 个强负样本全放行） | 同上，且是用户最在意的那一项 |
| 召回率 | 0.333 ~ 0.417 | **已知**广告域只有三分之一到四成会被拦到 |
| **无标注桶** | **0 / 96**（两次独立运行） | **本功能的全部增量 = 0**：模型没有发现任何静态名单之外的新广告域 |

**所以"精确率 1.000"与"这功能有用"是两件事**：一个几乎不乱叫、也几乎不抓东西的
模型让两个判据都变绿，而它的产出是零。`jev-1.13-free` 在当前阈值下**不足以支撑
"能过滤广告"这个目标**；要让它有用，得先弄清是阈值/提示词的问题，还是这个档位的
模型对"域名是不是广告基础设施"这件事本来就判不动（`--dump-unknown` 可以导出那批
域名做人工抽查，**那批是浏览记录，只能导到仓库外**）。

结论：
1. **默认关闭 + 演练模式这条设计约束不变**，而且现在有了更强的理由；
2. **不要把"判据通过"当成上线依据** —— 判据只覆盖"会不会搞坏上网"，
   增量证据是"无标注桶里有多少真的 block"，本次为 **0**；
3. 免密钥档随时可能 429，而"量到的是配额还是模型"只能靠限速运行来保证
   （`--sleep-ms` 的默认值就是为此改的）。
