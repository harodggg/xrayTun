## 给用户的动作：**换成这个新 App**；**不需要重装特权助手**；**设置里的「自动连回来」没有了**

依据（可复算）：

```bash
git diff --stat v0.9.1..HEAD -- crates/xt-helper crates/xt-tun crates/xt-proto
# → 三个 helper 侧 crate 零改动（空输出）
grep -n 'PROTOCOL_VERSION' crates/xt-proto/src/lib.rs     # 4（与 v0.9.1 相同，未变）
git diff --shortstat v0.9.1..HEAD                          # 54 files changed, 441 insertions(+), 5455 deletions(-)
```

协议号未变、helper 侧可观察行为未变 ⇒ 装不装助手都能用新 App。
本版几乎全在 `apps/desktop`、`apps/ui`、`crates/xt-core`，**净删 5455 行**。

### 1. 删掉了「自动重连 / 看门狗 / 网络监视」

这是本版最大的改动，也是**你上次的判断被写进代码**：

> 自动重连和看门狗本来就没什么用，解决不了网络问题，每一次都是我去连。

它当时的逻辑是：后台每十几秒探一次目标，连续失败若干次就判定「隧道死了」，然后自动重连或重建。
问题有三层，每一层都不是能靠调参修的：

1. **它检测不出「真的连不上」**：探不到可能只是那一个探测目标被墙、被限速、被 DNS 污染；
2. **它会把「连不上」变成一次你没同意的操作**：悄悄重建隧道、悄悄换出口，你只看到「刚才断了一下」；
3. **它的代价落在你的操作路径上**：判定要攒够失败次数，中间就是等待。

现在这些机制**整体不存在**：没有后台探测、没有自动重连、没有「上次是连着的所以这次自动连」。
连接失败就**如实告诉你原因**，什么时候再连由你决定。

### 2. 切换节点：**选择就用，没有回落**

* 你点哪个节点就用哪个。连不上时：**保留你的选择** + 给出真实原因，而不是偷偷切回上一个「好节点」
  —— 否则你根本不知道现在的出口是哪一个。
* 删掉了接管前的 **TCP 门禁**（先探一次 TCP，通了才允许切）。**这个判断本身就是错的**：
  TCP 连上不代表代理可用（还可能被中途重置），TCP 连不上也不代表不能用（可能只是探针被针对）；
  而它的重试等待**全落在你点「切换」之后的这几秒里**。

### 3. 启动/重建更快：就绪等待改成事件驱动

以前是「每 50ms 轮询端口，最多等 N 秒」，重试路径里还有 `sleep(700ms)` / `sleep(500ms)`。
现在改成**读核心自己的输出**：端口一就绪立刻继续；如果核心提前退出了，**立刻**报
`CoreExitedEarly(退出码)`，不再干等到超时。固定 `sleep` 已经删掉。

体感：启动和切节点的等待少了「凑够睡眠」的部分；失败时错误来得更早、也更有信息。

### 4. 诚实边界（本版必须说清）

* **真机 macOS 行为依然未验证**（开发机不是 macOS）：TUN 建卡与回滚、切换时隧道重建的真实耗时、
  helper 授权，都需要你在真机上用一次。**没有 macOS 机器 ⇒ 我拿不到这类证据**，
  本版只到「单测 + 编译 + CI + 云端 CI 等价运行」级别。
* **删掉了兜底，所以某些失败现在会直接暴露给你**。这是有意的：
  「它自己恢复了」和「你手动连的」必须能分清 —— 宁可给你一条真实错误，也不要给你一次没人同意的自动操作。
* 上一次（v0.9.1）的**审计同步**、位置缓存、判决父域继承都保持不变；审计同步仍是**默认关闭**，
  想用按 `docs/release-notes/v0.9.1.md` 第 1 节开一次即可。

## 这一版改的是「删掉假装能自愈的东西」

一句话：

> **探不到 ≠ 连不上 · 选择就用、不偷偷换出口 · 失败要立刻报，不要用 sleep 凑时间**

### 具体删掉了什么

* `apps/desktop/src/commands/core.rs`：`spawn_tunnel_watchdog`、`spawn_network_watch`、
  `spawn_connectivity_check`、`spawn_monitors`、`reconnect_if_needed`、`MonitorGuard`、
  `RECONNECT_ATTEMPTS/INTERVAL`、`SLEEP_THRESHOLD`、`FAILURES_BEFORE_REBUILD`、`tunnel_is_dead`、
  `should_auto_reconnect`、`should_keep_reconnecting`、`CoreStartOutcome`、`Egress`、`FailureExit`、
  `IntentDrop` 等；`CoreStartTrigger` 收敛到 4 个（用户连接 / 切模式 / 切节点 / 应用判决规则）。
* `apps/desktop/src/state.rs`：`RecoveryState`、`RecoveryOutcome`、`CoreRuntime.recovery`、
  `clear_recovering_notice`。
* `crates/xt-core/src/model.rs`：`AppSettings.auto_reconnect`、`AppSettings.was_connected`。
* `apps/desktop/src/commands/nodes.rs`：`switch_plan` / `SwitchPlan` / `settle_switch`（回落计划）。
* `apps/desktop/src/supervisor.rs`：接管前的 TCP 门禁与其中的重试等待。
* UI：设置页「自动连回来」整块、`types.ts` 对应类型、`ipc.ts` 的 `recoveryView`，
  以及顶栏/仪表盘/预览里的恢复态分支 —— **没有留下假的开关或死指示器**。
* 连带删掉断言「已删机制」的测试（Rust 与 UI 都有），**不是放宽断言，是删掉主张错误行为的测试**。

### 顺手修掉的

* `scripts/bump-release.py`：Cargo.lock 的「版本字段残留」检查以前会把**同版本号的第三方 crate**
  也算成残留，导致发布被误判卡住；现在只检查**没有 `source =` 的本地包**，并补了自测 T8b。
