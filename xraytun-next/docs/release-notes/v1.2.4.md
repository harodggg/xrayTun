# xraytun-next v1.2.4 —— 第一份真机反馈修掉的两个 TUN 致命问题（含上一版报错的真因）

> 你在 v1.2.3 上点了「启动」，拿到的是：
> `config_invalid: xray 判定配置非法: … Failed to start: main: failed to create server > interface name must be utunN, where N is a number …`
>
> **这句话在骗人**：配置没有写错。是我们「启动前的配置预检」在 macOS 上不成立。
> 这一版修掉它，以及修完之后必然撞上的第二个坑（核心继承不到 utun fd）。

## 一、这两处到底是什么（按代码顺序）

1. **误报「配置非法」（你看到的这一屏）**
   预检用的是 `xray run -test -c <config>`。上游 `main/run.go` 的顺序是
   **先 `startXray()`（真的创建入站）→ 再判断 `-test`**。于是「测试」阶段就要去建 tun 入站：
   macOS 上要么需要 root 建 utun、要么需要环境变量 `XRAY_TUN_FD` 指向 helper 建好的接口 ——
   而那个 fd 要等 helper `TunUp` 之后才有，预检却在它之前跑。
   结果：预检拿空名字去建卡 → `interface name must be utunN` → 被我们报成「配置非法」。
   **修法**：TUN 不再做 `run -test` 预检（在 darwin 上它证明不了任何事），
   配置错误改由核心进程自己报 —— 那才是同一件事的真话。

2. **核心继承不到 utun fd（修完第 1 条立刻会撞上）**
   daemon 从 helper 收到 fd 时按安全习惯打了 `FD_CLOEXEC`（不泄漏给之后 exec 的进程）；
   而**核心正是那个「之后的进程」**：带 CLOEXEC 的 fd 不会随 exec 传下去，
   xray 只会看到一个不存在的 fd 号（或干脆自己去建卡，然后因非 root 失败）。
   老仓库为同一个坑留过明确记录：「supervisor 在 spawn xray 之前必须显式清掉它」。
   **修法**：`xt-datapath` 在 spawn 前清掉 `FD_CLOEXEC`（失败就硬失败 —— 继续 spawn 只会
   得到一句指向错误方向的「没有 TUN 设备」）；spawn 之后把父进程这份 fd 关掉
   （核心持有自己那份，接口靠「helper 一份 + 核心一份」活着；不关会每次连接泄漏一个 fd）。

## 二、从你这屏能推断出来的好消息（但仍只是推断）

错误出现在「配置预检」这一步。按 `connect_tun_flow` 的顺序，它之前已经完成了：
导入节点 → 选为当前节点 → 点启动 → 壳拉起 daemon → **连接特权助手（root 服务）** →
**`DiscoverPhysical` 发现物理上行**。也就是说**特权助手安装/授权/服务在跑**这条最难的链路
已经从「没验过」变成了「至少走通到你这一步」。
但我读不到你机器上的日志，所以这只是**按代码顺序的推断**，不是直接证据 —— 你下次失败时，
界面下方已经会显示 daemon 日志路径（`~/Library/Logs/XrayTun/xt-daemon.log`）。

## 三、证据

- 本机可验：`cargo` 不能跑（老规矩），所以 Rust 侧由 CI 编译与测试；本机 `guard.sh` PASSED，
  UI 套件未改动。
- **新增单测** `clear_cloexec_makes_a_real_fd_inheritable`：用真实 `pipe(2)` fd + 真实 `fcntl`，
  断言「清完之后 FD_CLOEXEC 位为 0」——这条原语就是「核心能不能拿到 TUN」的唯一开关，
  不能用「看起来对」代替。
- TUN 的端到端仍然**只有你的真机能验**。这一版把两个已确认的拦截点修掉，
  但**不承诺**修完就能连上：后面还有 utun 接管、路由/DNS 提交、核心就绪这些只有真机才看得见的事。

## 四、请你这样再试一次

1. 装 v1.2.4，打开（未公证，DMG 里有 `首次打开请看这里.txt`）。
2. 节点页导入/选择 → 仪表板「启动」。
3. 如果**还是失败**：把错误框里那几行原文发我（或把 `~/Library/Logs/XrayTun/xt-daemon.log`
   的最后几十行发我）。现在错误要么来自核心自己（它是真话），要么来自 helper 的某个具体命令，
   两者都能直接定位 —— 不会再出现「预检替核心报错」这种误导。
4. 如果**连上了**：请顺手试一次「切换并立即使用」（应当走 断开 → 连接），再试「停止」和卸载助手。

## 五、仍然没有做到的（不许含糊）

- 未公证（Gatekeeper）以你真机为准；TUN 接管（utun/路由/DNS 的实际生效）**依然没有验收**。
- 订阅没有定时自动刷新；托盘「退出」只退界面、隧道继续跑。
- 探测（测试延迟）仍会临时起本机 xray 实例、用环回 SOCKS 端口量真实 TTFB（测量路径，不是产品入口）。
