# xraytun-next v1.1.4 · 修：侧边栏导航在真机上是「三个空灰条」

> 这是**真机截图**看出来的第一个纯视觉缺陷 —— 编译通过、单元测试全绿、逻辑全部正确，
> 但界面在用的时候导航是瞎的。

## 一、缺陷：侧栏只有当前那一项看得见

**症状**：左侧导航四个入口（状态 / 节点 / 日志 / 设置），**只有你当前所在的那一项有字**，
另外三项是三个看不见文字的浅灰色条。等于导航不可用 —— 你根本不知道另外三个入口是什么。

**根因**（两处叠加）：

1. 全局重置只写了

   ```css
   button, input, select, textarea { font: inherit; color: inherit; }
   ```

   接管了排版与文字色，**没有接管 `background`**。于是 `<button>` 保留 WebKit/macOS 的
   **系统按钮外观**（浅灰渐变底 + 高光描边）。
2. `.app__nav-item` 的文字色是 `--text-dim: #a7b3c6`，那是给**深色底**设计的。
   浅灰字画在浅灰底上 → 几乎不可见。选中项之所以正常，是因为 `--active` 覆盖了背景色。

`.btn` 从来没这个毛病，因为它自己显式写了 `background: var(--surface-2)`。

**修法**：给 `.app__nav-item` 补 `appearance: none` + `background: transparent` + `border: 0`，
并把文字从原生默认的**居中**改成**左对齐**（左侧竖向导航，左对齐才符合阅读顺序）。

**为什么以前没暴露**：`vitest` 跑在 jsdom 上，没有排版与绘制；dev 里也没有人真的肉眼看过。

## 二、交付加固（同一次排查里顺带修的）

- **DMG 打包失败不再连累 app 交付。** 原先 Release 只上传 `*.dmg`，而 dmg 打包依赖
  tauri 里的 Finder 自动化、在 CI 上**偶发**失败（实测过一次 `error running
  bundle_dmg.sh`）。一旦失败，这次发布就**没有任何 macOS 应用**可下。
  现在：`.app` 产出有硬断言；**永远**额外产出 `XrayTun_1.1.4_universal.app.zip`
  （已 ad-hoc 签名、CI 校验过）；dmg 与 zip 各自独立上传、存在才传。
- **冒烟升级为发布闸门**：打包出来的 `.app` 必须在真 macOS 上启动 30 秒后仍存活、
  且 `xt-daemon` 确实在跑，否则拦发布。「打包出来却起不来」从此不可能静默发出去。

## 诚实声明（不要跳过这一段）

- **未经公证**（没有 Developer ID 凭据）。Gatekeeper 拦下时：
  `xattr -dr com.apple.quarantine /Applications/XrayTun.app`
- **已知缺口：dmg 里的 app 还没签名。** tauri 是在打包过程中签名的，而我们的 ad-hoc
  签名发生在打包**之后** —— 所以 dmg 里装的是未签名版本，CI 校验的是 `.app` 与 `.zip`。
  也就是说：**zip 是我们验过的那个东西，dmg 不是。** 想避开这个缺口就下 `.app.zip`。
  真正的解法是 S5（Apple 凭据，tauri 会在打包时就签名）。
- TUN 接管、helper 安装/回滚、菜单栏交互仍**未真机验收**。
- 本次的证据来自 GitHub `macos-14` runner 上的真实 macOS 截图（状态页 + 设置页），
  **不是**你手上那台 Mac。它能证明「打包产物在真实 macOS 上能起来、界面正确、导航可读」，
  不能替代你自己的真机验收。
