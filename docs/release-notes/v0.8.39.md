> ## 给用户的动作：**本版不需要重装特权助手**
>
> 本版只改 **App 自身**（`apps/desktop/src/lib.rs`）。`crates/xt-proto`、`crates/xt-helper`、
> `crates/xt-tun` **一行未改**（`git diff v0.8.38..v0.8.39 -- crates/` 为空）⇒
> `PROTOCOL_VERSION` 仍是 2、助手协议不变。**为 v0.8.38 装过助手就不必再装。**

## 这一版为什么发：让崩溃留下证据

v0.8.38 出现过一次**启动即 `SIGABRT`**（release profile 是 `panic = "abort"`，
所以任何 Rust panic 都变成 abort）。而系统崩溃报告里只有一句 `abort() called`：

* 经 LaunchServices（双击图标）启动时 **stderr 不落在我们能读到的任何地方**；
* App 当时没有 panic hook；
* `[profile.release] strip = true` 还剥掉了符号。

⇒ 结果是我们**手上一点证据都没有**，连"哪个文件哪一行、什么消息"都不知道，本机也复现不出来。
这一版补上的就是这件事：`run()` 的**第一件事**变成装 panic hook，
把 **panic 位置（`文件:行:列`）+ 消息 + backtrace** 追加写到

```
~/Library/Application Support/com.xraytun.desktop/logs/panic.log
```

（同时保留终端里 stderr 的默认输出。）

**如果你再遇到启动崩溃**：把 `logs/panic.log` 的尾部发来即可 —— 位置字符串就在里面，
我能直接定位到出问题那一行，而不用再猜。

> 这一点如实说：hook 只让崩溃**可诊断**，它本身**不修**那个崩溃。上一次崩溃的根因
> 目前仍未知（本机两次复现均未成功）。有了 panic.log，下一次就能真的修掉它。
