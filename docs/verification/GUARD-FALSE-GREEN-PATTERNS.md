# 守卫假绿规范：判据离「用户可见结果」的距离 → 假绿方式

> **由来**：`task-157` 复核 `task-134` 时发现「守卫是文本判据，看着绿、实则可绕」，Lead 判定它与 `M3`、`M5 空改`、`grep -q`+SIGPIPE 假阴、`296 passed + Errors 1`、`.app` 自测第一版恒绿、探针用实现内部列表当判据是**同一族**。本文件把它固化成规范（`task-161`）。
> **用途**：写新守卫 / 做突变实验 / 读门禁结果 / 判「这条红是不是真的」时照此执行。
> **一条总原则**：**判据离「用户可见结果」越远，越容易假绿；能用行为级就不要停在文本级。**
> **证据强度**（每条实例都标，**不足以写死的不删掉，只降级**）：
> `★★★` = 我自己跑过并在仓库留档 · `★★` = 仓库内有原始留档但我未亲跑 · `★` = 仅转述/回忆，仓库无留档（**不得当作已验证事实**）。

## §1 距离模型（本规范的心智模型）

| 层级 | 判据读的是什么 | 典型形状 | 与用户可见结果的距离 |
|---|---|---|---|
| **L0** | **用户可见产物本身** | 界面文案 / 响应 JSON / 落盘文件内容 / 是否真的发出了请求 / 线上资源字节 | 0（就是结果） |
| **L1** | **驱动的行为**（走真实代码路径，只把外部世界换成替身） | 注入执行器 / 临时文件根 / 假时钟 ⇒ 断言返回值与副作用 | 1 步（可信，但**替身 ≠ 真机**） |
| **L2** | **结构/类型** | AST、枚举形状、`must_use`、编译期断言 | 2 步（能防"写法回来"，防不住"值被吞掉"） |
| **L3** | **文本** | `src.contains("rollback(&snap)?")`、正则、行号锚点 | 3 步（**本规范的主要风险区**） |
| **L4** | **工具的汇总/计数** | `296 passed`、`grep -c`、`Errors 0`、状态码 | 4+ 步（**禁止单独作判据**） |

**推论（可直接执行的规范）**：
1. **L0/L1 可判"实现对不对"；L2/L3 只能判"写法像不像"** —— 后者对「保留受检文本 + 运行时吞掉」**原理上不可判定**（§2 R1/R2）。
2. **L4 只能当"筛子"，不能当"判据"**：必须同时读**退出码**与**错误行**（§2 R5）。
3. 判据与被测实现**共用真源**时，任何"把真源清空"的突变会**同时关掉探测器** ⇒ 假绿（§2 R4）。

## §3 决策表：什么时候必须升级

| 情境 | 必须做什么 | 理由（对应实例） |
|---|---|---|
| 判据的结果**用户能看见**（界面文案、响应体、退出码、落盘内容、是否真发出请求） | **必须 L0/L1 行为级** | R1：V-1/V-3 能让响应说谎而守卫全绿 |
| 站点**有可注入接缝**（执行器/时钟/文件根/HTTP 替身） | **必须用它做行为级**；并**产物级证明生产路径无钩子** | `task-134` 的 `#[cfg(test)]` 接缝本身就是为此加的；**零开销与无注入入口**要看产物，不是看注释（`TASK-134-A1-SEAM-VERIFY.md` §2：非测试 IR 里 `run` = `call @real_run; ret void`、接缝符号计数 0） |
| 站点**无法注入**（要 root / 真机 / 外部服务） | 文本守卫**可作第二道**，但必须：① **站点级块判据**（不是全文件 `contains`）；② 报告里**逐条列出已知不可判定的写法**（诱饵、跨语句别名）并留档；③ 一旦具备注入条件**立即**补行为级 | R1/R2：这正是 `task-160` 的 (b)；但 **(b) 只能收窄、关不死** |
| 判据是**集合/白名单/过滤**类 | **必须独立真值源**（不得从被测实现内部取值） | R5：`NodeAddresses` 假绿 |
| 判据是**聚合数字**（计数、`Errors 0`、状态码） | 禁止单独作判据；必须 **退出码 + 错误行 + 至少一条正向可观测产物** | R6/R8 |
| **编译/类型层** | 与运行层**分别**判定，不互相抵消 | R6 类型层孪生；R7 编译错误冒充结论 |
| **突变实验** | 必须证明：**改到且改对** + **编译成功** + **行为确实不同** + **测试真的跑了** | R3/R4 |
| **反向用例**（把缺陷放回去） | 必须红，且**红的断言就是这一条**；全红时先怀疑"整体崩了" | R7 ②③ |

## §4 写新守卫时的自检清单（逐条打勾，不许"看起来对"）

**A. 真值源**
- [ ] 判据取值是否来自**被测实现内部结构**？若是 ⇒ 换成独立真值（配置/落盘产物/服务端/用户可见输出）。
- [ ] 这条判据能区分「**实现没做**」与「**实现在但没被调用**」吗？（站点真的被驱动了吗？钩子真的只在测试里吗？）
- [ ] 我的 fixture 是否复用了被测代码的构造逻辑？（T1 拷全 3 个 ⇒ T3 恒绿那类）

**B. 突变有效性**
- [ ] 我的突变**证明过编译成功/落盘**吗？（编译失败/锚点未命中 ⇒ **结论作废**）
- [ ] 突变**改变了行为**吗？能指出它走了**不同分支**吗？（空突变 ⇒ 结论无效）
- [ ] 我用的是**精确锚点 + 断言唯一**，还是全局替换？（全局替换会改坏别的字面量 ⇒ `unexpected closing delimiter`）
- [ ] 还原后核对过 **sha256 / `git status`** 吗？（别用 `git checkout` 把探针一起还原 ⇒ 0 个测试匹配、退出码 0）

**C. 读什么数**
- [ ] 我读的是**退出码**还是**汇总数字**？（两者 + **错误行**都要）
- [ ] 有没有把 `0 passed; 0 failed` / `0 tests matched` / "没跑" 当成绿？
- [ ] 我确认过测试**真的跑了**（而不是被 filter 掉）吗？
- [ ] **类型层**（tsc / clippy 的 warning）与**运行层**是否分别读了？

**D. 反向与边界**
- [ ] 反向用例（把缺陷放回去）**真的红了吗**？红的**位置/断言**是这一条吗？
- [ ] **全红**时我是否先怀疑"整体崩了"而不是"断言在验它"？
- [ ] 我验证过「**不该受影响的用例仍然通过**」吗？
- [ ] 工具的假信号（管道退出码/SIGPIPE、环境串味、stale 产物、共享工作区别人的在途改动）排除过了吗？

**E. 结论措辞**
- [ ] 我写的是「**我量到的**」还是「**我推断的**」？
- [ ] 替身覆盖是否明确标注 **≠ 真机验证**？
- [ ] 若某条只有间接证据，是否标了**证据强度**而不是删掉？

## §5 三种升级模式（可直接照抄的形状）

**M1「行为级替换」**（首选）：给站点引入**只在测试构建存在**的接缝（`#[cfg(test)]`），断言**用户可见产物**
（响应文案 / 落盘文件 / 是否发出请求 / 退出码）。**并产物级证明生产路径无钩子**
（例：`run` 的非测试 IR = `call @real_run; ret void`，接缝符号在生产 IR/二进制里计数 0 —— `TASK-134-A1-SEAM-VERIFY.md` §2）。

**M2「站点级块判据」**（文本守卫的第二代）：不做全文件 `contains`，而是
「定位站点**自身的 handler 块** + 要求块内把错误**绑定**并**流入**用户可见产物」；
并把**已知不可判定**的写法（诱饵调用、跨语句别名/清空）在报告里列明为"本层不可判定"。

**M3「独立真值源」**：判据只读外部可观测产物；**自检动作** —— 把实现内部集合**清空**的突变必须仍然**红**
（`NodeAddresses` 那次就是这条自检没做）。

## §6 诚实清单（本规范测不到什么）

1. **本规范不能证明任何具体守卫"没有假绿"**：它只列已知模式与检查动作；§4 的清单能降低概率，不能给出证明。
2. **「假绿」的定义边界**：本规范只覆盖「判据跑出来是绿的，但它与用户可见结果脱钩」。
   **不覆盖**：(a) 需求理解错误（判据忠实于错误需求）；(b) 从未被执行到的代码路径（没有判据可谈）；
   (c) 概率性 flake（同一判据时红时绿，那是另一族）。
3. **未观测到的假绿无法穷举**：新工具、新 CI、新替身都会带来新形状；本规范的价值是**可增长**，不是完备。
4. **证据强度已逐条标注**，其中最弱的是 **`323 passed` + `TSC_EXIT=2`（`★`）**：Lead 转述，
   我检索全仓与 `/tmp` 日志**均无留档**，我**未复现**；它在表中**只作同族提示**，不构成既定事实。
5. **我未亲跑的条目**（`★★`）：`grep -q`+SIGPIPE、`.app --self-test` 第一版恒绿、stale artifact 假绿、
   线上 200 假绿、共享工作区 tsc 假红 —— 引用的是团队留档（§7 有提交号），不是我的一手测量。
6. **有一条我亲跑但原始输出只在临时日志**（R4① 的 `unexpected closing delimiter`）：原文已引在 §2.3，
   仓库内**没有**该日志 ⇒ 该条为"我亲历 + 本规范内引用"，无法从仓库重新生成同一条日志（harness 是临时的）。
7. **本规范不评价"文本守卫该不该存在"**：在无法注入的站点，文本守卫是**唯一**可自动化的防线，
   它的价值是**拦住低成本回归**，不是**证明正确**。
8. **本规范不覆盖真机**：所有行为级示例都是"替身覆盖"，与真机行为之间仍有差距（见各报告自己的诚实清单）。
