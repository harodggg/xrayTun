
同一文件三种跑法的实测：

**对 DoD #1（`npm test` 全绿）的影响 —— 更正**：**单跑可达且全绿**。最终两次独立复跑

`logsDomStability.test.tsx` 在这两次里**全绿、无超时**。⇒ 结论：**不是"本机不可达"，
而是"多进程并发跑才会踩 5000ms 默认超时"**（并发时 CPU/事件循环被抢，94s 那一条被 5s 默认线截断）。

### 4.1 验证者自己的两次"假绿/假红"事故（留档，不删）

1. **假红**（Lead 发现）：mutant 副本最初直接放在 `__verify09__/mutants/`，其相对 import
   （`../ipc`）解析到不存在的 `__verify09__/ipc` ⇒ vitest 报 `Tests no tests` + rc=1。
   我第一版把它当成"判据有牙"，等于用加载错误冒充判据。修法：把 mutant 里的相对 import
   全部重写为指向真实文件的绝对路径；并加**校准案件**（写坏的副本必须红）与
   "必须出现 `Tests N failed`，否则判假红并作废本次结论"的硬校验。
2. **假绿**（S3 暴露）：D1 探针第一版查全局 `[stroke-dasharray]`，而图例的 `<line>`
   与 `.flow__highlight` 都有该属性 ⇒ "只改图例、渲染路径没改"也能通过。
   修法：只查 `path.flow__route[stroke-dasharray]`，并用假锚点（jsdom 无布局引擎，
   `getBoundingClientRect` 全 0 时 Flow 不画）让渲染路径真的出现。
