# 0.9.0 · 用户测试方案（journey 级走查）

> 作者：Lead · 基线：`bd4f4d3`（v0.8.45）
> **先说清楚这是什么、不是什么**（本项目红线：不许把推断说成事实）：
>
> * 这**不是**用户研究：没有真实用户、没有访谈、没有遥测。仓库里从来没有任何用量数据
>   （四份审计都如实写了这一点）。
> * 这**是**一次**结构化的可复现走查**：把 0.9.0 承诺的「每个动作都有回声」翻译成
>   **可断言的用户可见事实**（出现了什么文字、几次点击、几次页面切换），
>   用仓库既有的 `?preview=1` 状态夹具 + vitest/jsdom 跑；只有真机才能看的部分单列人工清单。
> * 「高频/低频」仍是**推断**（来自 `docs/optimization/UX-AND-HABITS.md` §2 的用户原话与设计文档），
>   用它排序候选，但**不作为通过/失败的判据**。

---

## 1. 为什么要有 journey 级测试（而不是只加组件测试）

0.9.0 的承诺是**跨组件的**：
「点一个开关之后，屏幕上必须出现一句人话」这件事，组件单测会分别断言
「开关触发 `save_settings`」与「横幅组件能渲染文本」——两条都绿，**用户仍然可能什么都看不到**
（横幅挂在了另一个分类下、或挂在滚动区外）。

所以每个 journey 至少一条断言必须**从用户动作出发、到可见文本结束**，
中间不许用「调用了某个函数」代替。

## 2. 五条 journey 与判据

点击/切换的基线数字取自 `docs/optimization/UX-AND-HABITS.md` §2（代码路径枚举，非实测点击）。

### J1 · 第一次连上（新用户）

| 项 | 基线 | 0.9.0 目标 |
| --- | --- | --- |
| 点击 | 5（打开→订阅页→添加→节点页→选节点→连接） | **4**（空态仪表盘直接「添加订阅」→添加→选节点→连接） |
| 页面切换 | 3 | **2** |
| 必须出现的可见文本 | — | 空态主按钮文案 = 「添加订阅」；点它落到订阅页（不是节点页） |

**判据（可断言）**：在「没有任何节点」的快照下，仪表盘的第一个主按钮文本为「添加订阅」，
点击后当前视图为 `subscriptions`。**反向判据**：有节点时该按钮必须是「切换节点」→ `nodes`。

### J2 · 换个节点（高频，应急时也常用）

| 项 | 基线 | 0.9.0 目标 |
| --- | --- | --- |
| 点击 | 2（侧栏→点行） | 不增加（**换节点不许加确认**） |
| 必须出现的可见文本 | 无（基线实测 `anyWarning: []`、`spinner: 0`） | 「正在切换到「<节点名>」，隧道会重建几秒」（含**目标节点名**） |

**判据**：点某一行后，页面上出现包含该行节点名的进行中文案。**反向判据**：文案必须含**被点的那个**节点名
（不是"当前节点"或泛指），否则用户无法确认自己点对了。

### J3 · 改分流（中频，排障时）—— 基线已完成，**回归**

| 项 | 0.9.0 目标 |
| --- | --- |
| 必须有 | 切换预设后出现「已保存」+「重新连接后生效」+ 可点的「立即重连」（`Routing.tsx:395-412`） |
| 不许有 | 静默生效（无任何反馈） |

### J4 · 排查连不上（1–3 次点击，但要 5+ 概念）

| 项 | 0.9.0 目标 |
| --- | --- |
| 必须有 | 失败时给出**下一步动作**（换节点 / 看日志 / 报告问题），而不是只给错误码 |
| 必须有 | 结论区分「本机网络」「节点」「运营商」三类里的**具体一类**，或如实说"无法区分" |
| 诚实边界 | 本机网络探测属 `commands/core.rs` 的**未实现**项（UX 审计 §2 T4 明确登记）→ 本 journey 本轮**只做回归，不新增** |

### J5 · 看还剩多少流量（低频但重要）

| 项 | 0.9.0 目标 |
| --- | --- |
| 必须有 | 订阅页每张卡直接显示「已用 / 总量 / 到期」（基线已合格） |
| 不许有 | 「流量不可用」时显示 `0`（诚实三做不到之一） |

## 3. 怎么跑

### 3.1 自动（本机可跑，覆盖 J1/J2/J3/J5 的文案与导航）

```bash
cd apps/ui && npx vitest run src/journeys09.test.tsx
```

* 用仓库既有的 `?preview=1` 状态夹具（`previewSnapshot.ts`）与 `StoreProvider`；
* 断言**用户可见文本**与**视图切换**，不断言实现调用；
* 每条 journey 都配一条**反向判据**（"不该出现什么"或"必须含哪个具体值"），
  防止「文案存在但写错对象」这种最常见的假绿。

### 3.2 人工（只有 macOS 真机能看，**本机做不了**）

| 项 | 怎么看 | 为什么自动化不了 |
| --- | --- | --- |
| `⌘,` 打开设置 | 按一下，落到设置页 | 需要 Tauri 菜单 + WKWebView，无 CDP |
| helper 安装/卸载流程 | 真装一次，看授权弹窗与「后台允许」提示 | 需要 root + 系统设置 |
| TUN 建卡与回滚 | 连上→断开→`ifconfig utun` 与 `scutil --dns` | 需要内核接口 |
| 换节点真实重建耗时 | 掐表：点行→新节点可用 | 预览是瞬时返回的假后端 |
| `Esc` 关面板 | 打开拓扑详情/导出模态后按 `Esc` | 键盘在 jsdom 可用，但**真机焦点**不同 |

**人工清单的结论一律标注「未验证（需 macOS 真机）」**，不得写成"已验证"。

## 4. 评分与门槛（0.9.0 Definition of Done 的一部分）

| 等级 | 含义 |
| --- | --- |
| ✅ | 自动断言跑通（或人工项在真机确认） |
| ⚠️ | 只做到部分（例如文案出现但不含目标节点名）→ 记为缺陷，不阻塞发版但必须登记 |
| ❌ | 判据不成立 |
| ➖ | 本轮明确不做 / 需要真机但拿不到，且**已如实登记** |

**门槛**：J1/J2/J3/J5 全 ✅ 或 ➖ 才允许对外称 0.9.0 达标；J4 允许 ➖（其根因是后端未实现本机网络探测，
属下一轮）。

## 5. 已知会污染结论的两件事（写下来防止后人误读）

1. **`?preview=1` 是 mock 后端**，命令瞬时返回。因此「换节点 1.4 秒内没有 spinner」这类
   **时间**结论在预览里**不可测**（基线审计已经踩过一次：用预览否定了一个真实的时序问题）。
   本方案的 J2 只断言**文案是否出现**，不断言它多久出现。
2. **jsdom 没有布局**：`getBoundingClientRect()` 恒为 0。凡是 PRD 里写「top < 636」的几何判据
   （P0-2 拓扑首屏、P0-3③ 地球仪首屏）在本机**无法自动验证**；本方案对它们改用
   **DOM 顺序**作等价判据（顺序对 → 首屏优先，这是可离线证明的部分），并在报告里
   明确写「像素级结论未验证」。
