# 隐私说明：审计自动同步（面向用户，可直接引用）

本页说明「意图判定审计自动同步」开启后，云端会**存什么、能看到什么、存多久、怎么撤回**。
每一条都与代码一一对应：端点源码 `infra/audit-collector/src/worker.mjs`，
契约 `docs/design/AUDIT-SYNC.md`。

## 一句话

**只存你设备加密后的密文；服务端没有密钥、解不开；不存 IP、不开请求日志；400 天后自动删除；
你随时可以撤回全部已上传。**

## 1. 存什么

只存**一个对象/天**：R2 key `audit/<device>/<day>.json`，内容是设备发来的**密文信封**
（原样字节，不重新序列化）：

```json
{ "v": 1, "alg": "chacha20poly1305", "device": "<16hex>", "day": "2026-09-24",
  "rows": 123, "bytes": 45678, "nonce": "<24hex>", "ct": "<hex 密文+tag>" }
```

| 字段 | 明文/密文 | 说明 |
|---|---|---|
| `ct` | **密文** | 当天的审计行的完整密文。**没有设备密钥就无法还原任何内容**，包括域名 |
| `nonce` | 明文 | 每次加密随机生成的 12 字节随机数（不泄漏内容） |
| `device` | 明文 | 首次开启同步时随机生成的 **8 字节** id（见 §2） |
| `day` | 明文 | 该天的 UTC 日期 |
| `rows` | 明文 | 该天的审计行数 |
| `bytes` | 明文 | 明文长度的**估算值**（仅人读；不参与认证） |

**服务端没有解密能力**：它不持有设备密钥，也不在任何地方生成/保存密钥。密钥只在你本机的
数据目录里的 `audit-sync.key`（0600，与 `intent-audit.jsonl` 同级同权限；契约 §5.1 说明了
为什么这一版不是 Keychain）。也因此服务端**不提供图表、不做聚合** ——
这不是缺陷，是这条管线的前提（契约 §7）。要分析就本机拿密文 + 密钥解。

## 2. 明文头里能看到什么（**如实说**）

即使只有密文，下面这些**服务端与任何能读到 R2 的 Cloudflare 账号侧都看得到**：

* **设备随机 id**（8 字节 hex，**不是**硬件指纹、不含账号/机型/序列号信息）；
* **日期**与该设备**每天是否上传**；
* **行数 `rows`**；
* **密文长度**（对象大小，≈ 明文长度的 2 倍，因为用了 hex）；
* **上传时刻**（R2 对象的创建时间）。

⇒ 这些**足以做流量模式分析**（例如「某个 id 连续 30 天每天都有数据」）。
**所以不能说「完全匿名」** —— 我们只能说「看不到内容」，不能说「看不到任何信息」。
这是刻意的取舍：`device`/`day` 必须是明文，服务端才能按设备分组、列出与撤回（契约 §5.2、§7）。

## 3. 不存什么（刻意不采集）

| 不存 | 说明 |
|---|---|
| **客户端 IP** | 我们**不把 IP 写进 R2**。端点需要防滥用，所以做「按 IP 的限流」，但键是 **`SHA-256(每 isolate 随机 salt + IP)` 的前 16 个 hex**，**只在内存里**，isolate 重启即消失，也不进持久层。 |
| 请求日志 | Worker **未开启** observability（`wrangler.toml` 里 `[observability] enabled = false`），不采集请求日志。 |
| User-Agent / 设备指纹 | 不记录。 |
| 明文审计内容 | 从不接收、从不存储 —— 上传前已在本机加密。 |
| `context_sent`（页面内容） | 契约 §2 硬规则：无论设备上是否开启「记录外发内容」，bundle 一律剥掉；它根本不会出现在密文里。 |
| settings / 订阅 / 节点 / 定位缓存 | 其它管线的事，本端点不接收。 |

## 4. 存多久

**400 天**（建议值，契约 §4），两道保证：

1. **R2 lifecycle 规则**（`expire after 400 days`）——存储层自动删除（主机制）；
2. **端点内的惰性过期**（**只对被 `list` 到的对象生效**）：`list` 会把上传时间超过
   `RETENTION_DAYS` 的对象当作过期、顺手删掉；`uploaded` 拿不到时不判过期（不猜）。
   `revoke` 与年龄无关，一律全删。

> 为什么把「只对被 list 到的生效」写出来：incident-collector 的 lifecycle 规则曾经**事实上不存在**
> 过一段时间（命令写错又被 `|| true` 抹平，见其 `PRIVACY.md` 与 `README.md`）。
> 只写「两道保证」而不写各自的作用范围，容易把「有惰性过期」误当成「反正会删」。

## 5. 谁能读

| 内容 | 谁能读 |
|---|---|
| 密文对象 | Cloudflare 账号持有者（= 用户本人）与持有该账号 API token 的维护者。**但读到的只有密文**，没有设备密钥仍然解不开。 |
| 明文头元数据 | 同上（就是 R2 对象本身，见 §2）。 |
| 密钥 | **只有设备本机**（数据目录 `audit-sync.key`，0600）。服务端任何时候都没有。 |

## 6. 怎么撤回 / 删除

1. **随时、端到端**：`POST /api/audit/revoke`（`{"device":"<16hex>"}`，带 `Authorization: Bearer <token>`）
   会**分页列出该设备前缀下的全部对象并逐个删除**，返回 `{"ok":true,"deleted":<n>}`。
   设备侧 UI 的「撤回全部已上传」就是这个（撤回前必须二次确认，契约 §8）。
2. **到期自动**：400 天后 lifecycle 删除（见 §4）。
3. **彻底停止**：维护者 `npx wrangler delete --config infra/audit-collector/wrangler.toml`
   （摘掉端点）+ `npx wrangler r2 bucket delete xraytun-audit`（清空数据），再吊销 Cloudflare API Token。
   步骤见 README「回滚 / 撤销」（桶名就是 `xraytun-audit`，写错只会返回 `bucket not found`
   —— 而这一步最不该失效）。
4. **关闭同步**：关闭开关后调度器**零网络请求**（契约 §5.4），但**不会自动删除已上传的数据** ——
   要删就用上面的 `revoke`。

> ⚠️ **密钥丢失的后果**：设备密钥丢了 ⇒ 已上传的密文**永久读不出**，只能撤回删除。
> 本机的 `intent-audit.jsonl` 始终是第一副本，所以不会因此丢历史（契约 §5.1）。
> 密钥**可以导出用于备份**。

## 7. 已知边界（如实说）

* 明文头元数据可做流量模式分析（§2）⇒ **不是「完全匿名」**；
* 限流是 best-effort（每个 Cloudflare isolate 一份内存），**非授权判据、不构成安全边界**；
* `rows` / `bytes` 由设备自述、不参与认证，服务端仅原样转发；
* 密文本身服务端无法验证：持有 token 者可覆盖某天的对象（污染），这是 E2E 的直接后果（契约 §7）；
* 数据存放在 Cloudflare R2，受 Cloudflare 的服务条款约束。
