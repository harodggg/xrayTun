## 关于事实的标注

文档里所有涉及系统行为与 Xray 行为的陈述都标注了核实方式：

* `[实测]` —— 有对应的单元测试，或通过系统头文件/命令验证过；
* 「（读上游源码核实）」—— 通过拉取 tag 归档并阅读源文件确认；
* 「（计划中）」「（待实现）」—— 尚未落地。

这样做的原因是：这个领域里流传着大量彼此矛盾的「常识」。
本项目在开发过程中就推翻了三个：

1. **macOS 支持 `AF_UNIX` + `SOCK_SEQPACKET`** —— 不支持，`EPROTONOSUPPORT`；
2. **Fake-IP 是 sing-box 独有的** —— Xray 有原生 `fakedns`；
3. **Xray 没有原生 TUN 入站** —— v26.1.18 起有，v26.1.31 起在 macOS 上完整可用。

每一个都把设计带向了不同的方向。所以「写下依据」不是文档洁癖，
而是让下一个人能快速重新验证，而不是重新踩一遍。
