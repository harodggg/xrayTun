> ## 给用户的动作：**本版必须重新安装特权助手**
>
> 依据：本版改了 helper 自身的身份校验策略 —— `crates/xt-helper/src/peer.rs` 新增
> **cdhash 绑定**（对端可执行文件的 cdhash 必须逐字节等于已安装 App 的），并把宽松策略
> 收紧到**只在 debug 构建存在**。装旧助手的机器上这道门与新版对不上，因此请重新安装一次。

## 这一版修的最重要一件：**双击打不开**

真实事故：0.8.38/0.8.39 装上后**双击即崩**（`SIGABRT`）。根因已定位并有真机证据：

```
apps/desktop/src/lib.rs:178:17  there is no reactor running, must be called from
the context of a Tokio 1.x runtime
```

Tauri 的 `setup` 回调**不在 Tokio runtime context 里**，而那里调了裸 `tokio::spawn` ⇒ panic；
release profile 是 `panic = "abort"` ⇒ 进程直接 abort。修复：统一改走 `tauri::async_runtime::spawn`
（并扫掉同类调用）。验证是**差分**的：修复前的 App `--mode direct` 3/3 `Abort trap: 6`，
修复后 3/3 绿；同时把 panic 的位置写进 `logs/panic.log`（App 起不来时也能拿到证据）。

## 安全：两条 P0 + 一条产品级死结

* **helper 的签名门形同虚设**：`LOCAL_PEERTOKEN` 曾写错成 `0x005`（实为 `LOCAL_PEEREUUID`），
  取到的是半截 token ⇒ 即便注入 Team ID，合法 App 也会被一律拒；已改用 `libc::LOCAL_PEERTOKEN`
  并强制 32 字节。
* **根证书会永久残留**：会话仍自认 `Up` 时崩溃/重启会让 `restore_stale` 早退、下次 `TunUp`
  又覆盖快照 ⇒ 旧根证书留在系统钥匙串且无记录、用户再也删不掉。已改成**只要快照里有锚就无条件撤销**，
  新会话**继承**旧锚记录。
* **没有证书时的身份绑定（新）**：没有 Developer ID 时，helper 改为要求**对端 cdhash == 已安装 App 的 cdhash**；
  找不到已安装 App 则**拒绝一切非 root 特权操作**（fail-closed），而不是"信任任何对端"。
  如实说明边界：它挡不住**有能力替换 `/Applications` 下 App** 的攻击者 —— 那已经需要管理员/root。
* **根证书有效期**：rcgen 的默认有效期是 `1975 → 4096`（等于永不过期），本版显式设置有效期并把到期日回传界面。

## 其它

* 界面不再撒谎也不再吓人：错误给**人话 + 下一步可点动作**（换网络 / 换节点 / 重装助手 / 看日志）；
  修掉了"连不上服务器却建议你换本地端口"这类**步骤错配**；tooltip 与读屏 live region 不再逐字念出 `**`；
  日志页常驻 `panic.log` 路径；界面黑屏时会给出可见报错与可复制原文。
* 门禁补上盲区：新增「App 启动路径守卫」（禁止 `setup` 里出现裸 `tokio::spawn`），
  并加了"过滤器匹配 0 条"这类假绿的反制断言；发版流程预检从 `Cargo.toml members` 派生成员清单、
  真版本字段残留一次列全 —— 发版不再能停在"正在发布"的中间态而没人知道。
