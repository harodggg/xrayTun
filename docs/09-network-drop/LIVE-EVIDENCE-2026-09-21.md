> **为什么这份文件在仓库里**：这些读数**无法再复现** —— 采集窗口里 XrayTun 处于 TUN 连接态，
> 而原始记录原本只写在 `/tmp`，**`/tmp` 会被清**。本项目已经栽过一次

## 4. 这份证据**确立**了什么（逐条标注证据强度）

| 结论 | 强度 |
|---|---|
| 「`127 → 局域网路由器`」这条路由**只在与 XrayTun 连接时存在，断开后消失** | **实测**（连接态 4 次采样有、断开态 6 次采样无） |
| 连接态下 `127.0.0.2` / `127.0.0.53` **实测不通**；`127.0.0.1` **实测通** | **实测** |
| 该路由的来源是「所有 IPv4 bypass 网段一律指向物理网关」（`crates/xt-tun/src/plan.rs`） | **读码**（并有实读的完整 bypass 清单与之一致） |
| 国内流量走 `direct`、其余走隧道（`geosite:cn`/`geoip:cn`） | **读码**（实读 config.json） |
| 换网后 `direct` 仍绑旧网卡 + 换网监听只写日志不重建 + 看门狗只探境外 ⇒ 国内断、国外正常、不自愈 | **读码**（`core.rs`）→ **已修**（`d3e0c95`） |

## 5. 这份证据**没有**确立什么（不许当成结论）

* **它不能解释「连不上 `127.0.0.1:3080`」**：连接态下 `curl 127.0.0.1:3080 → 401` **实测仍是通的**，
  而 `127.0.0.2:3080 → 000` 是因为**那个地址上本来就没有服务**，**不是**回环判据。
  ⇒ 该症状**仍未定论**，需要在故障发生的那一刻取证（判据用 `ping 127.0.0.2`，
  **不要用「curl 某个端口」**，那会被「端口上没有服务」污染）；
* 本文件的读数**全部来自这一台机器、这一个时间窗**，**不是**对其它机器/其它网络环境的普适结论；
* 采集窗口内**没有发生过换网**，所以「换网 ⇒ 国内断」这条**没有现场记录**，只有读码与单测支撑。
